先に結論だけ書くと、こうです。

> 「安いモデルに投げて戻すと、かえって高くつく」という計算が載っています。式は正しく、私が再現したら著者の言う「pure opus は 2/3 のコスト」がぴったり出ました。ただし**使われている Sonnet の価格が1世代前**でした。現行価格に差し替えるだけで優位は 33% → **12%** に縮み、キャッシュ読みも計上すると **5%**、ほぼ互角になります。結論は「ルーティングは効かない」ではなく「**今の価格では誤差の範囲**」でした。

## 「KVキャッシュがなかったら」という問い

先に良いところを書きます。この文書の中心にあるのは1つの問いです。

> One of my favorite questions I ask people here is “**how would you design a coding agent if LLMs had no KV cache?**”

LLM に KV キャッシュがなかったら、コーディングエージェントをどう設計するか。

良い問いだと思います。いま当たり前になっている設計の多くが、実は「キャッシュを壊したくない」という制約から逆算されたものだからです。著者はこれを "the tyranny of the KV cache"（KVキャッシュの専制）と呼んで、6つ挙げています。

| # | 主張 |
| --- | --- |
| 1 | **ルーティングが効かない**（唯一、計算つき） |
| 2 | ツール定義は先頭で全部宣言する必要があり、文脈を食う |
| 3 | コンパクションは「全ターンが1つの状態を共有する」前提でしか正当化できない |
| 4 | サブエージェントがいまいち（状態の受け渡しが面倒だから） |
| 5 | 再起動という発想自体が、状態が壊れる前提から来ている |
| 6 | 電池同梱（batteries included）にするかどうかの綱引き |

3番が個人的に刺さりました。コンパクションは圧縮の問題を解こうとしているが、**何を探しているか分かっていれば圧縮ははるかに簡単**なので、クエリを知らないまま圧縮するのは一番難しい形をわざわざ選んでいる、という指摘です。

![設計図を裏返して、その裏に「KVキャッシュがなかったら？」と書いてある](/images/recomputing-the-routing-math/01-turn-the-blueprint-over.png)

## 計算を引き直した

6つのうち、数字が入っているのは1番だけです。

前提は opus が入力5 / 出力25、sonnet が入力3 / 出力15（100万トークンあたりドル）。X = 文脈トークン、Y = 出力トークン、Z = コマンドやファイル読みで生成される追加トークン。

- **経路1（opus 単独）**: 25Y + 5Z
- **経路2（opus → sonnet → opus）**: 3X + 20Y + 8Z

経路2に 3X が付くのがポイントです。sonnet は文脈をゼロから読み込む必要がある。opus 側はすでにキャッシュに載っているので読み直し料がかからない。これが「専制」の中身です。

比率は著者が置いています。そしてその置き方が、これ以上ないほど正直に書いてあります。

> let's have chatgpt **vibe** some proportion of X / Y / Z
> X = 0.65, Y = 0.12, Z = 0.23

ChatGPT に適当に出させた。そう明記されています。

この値で計算すると 4.150 / 6.190 = **0.670**。著者の言う「pure opus は 2/3 のコスト」がそのまま出ます。**式も算術も合っています。**

![精密な計算機の投入口に、手でちぎったメモを差し込んでいる](/images/recomputing-the-routing-math/04-the-vibed-input.png)

引っかかったのは価格のほうです。sonnet の 3 / 15 は **Claude Sonnet 4.6 の価格**で、現行の Claude Sonnet 5 は **2 / 10** です。差し替えて引き直しました。

| 条件 | opus単独 | 経由ルート | 比率 |
| --- | --- | --- | --- |
| 元記事のまま（Sonnet 4.6 価格） | 4.150 | 6.190 | **0.670**（33%安い） |
| Sonnet 5 の現行価格に差し替え | 4.150 | 4.710 | **0.881**（12%安い） |
| さらに opus のキャッシュ読みを計上 | 4.475 | 4.710 | **0.950**（5%安い） |

3行目について補足します。元の式は経路1に X の項が1つもありません。opus の文脈は「キャッシュに載っているからタダ」という扱いです。実際にはキャッシュ読みは通常入力の約0.1倍で課金されるので、opus 側にも 0.5X が乗ります。それを入れると差は5%。

**ChatGPT に推測させた比率が5%も動けば、符号が変わります。**

つまりこの計算が支えているのは「ルーティングは効かない」ではなく、「**現行価格では、どちらが安いか計算では決まらない**」です。結論の向きは同じでも、強さがまるで違う。設計判断に使えるかどうかが変わります。

![天秤。古い分銅では大きく傾き、新しい分銅に替えるとほぼ水平になる](/images/recomputing-the-routing-math/02-swap-the-weights.png)

なお私が使った価格は、手元の資料（2026年6月24日時点）の表です。Sonnet 5 が 2 / 10、Opus 5 が 5 / 25、キャッシュ読みが約0.1倍、キャッシュ書き込みが約1.25倍。**今日時点の公式価格で再確認はしていません。** 私の数字のほうが古い可能性は残ります。

## 私の見解

この文書を叩く記事ではありません。**検算できる形で書いてあるものは、それだけで価値がある**というのが私の立場です。

比べてみます。前に読んだ別のガイドは「本番のツール呼び出しは3〜15%失敗する」を土台にしていて、出典を辿ったら個人ブログ1本に着きました（[私の記事](https://meikocho1.github.io/blog/three-to-fifteen-came-from-one-blog)）。あれは検算のしようがない。今回のは違って、式が全部書いてあるので価格を差し替えるだけで追試できます。しかも「ChatGPT に vibe させた」と自分で書いている。**弱いところを自分で明示した文書は、読者が直せます。**

そのうえで、一番怖いところを書いておきます。**この文書は、著者が「もう1つエージェントを作る」理由を説明するために書かれています。** 6つの「専制」はどれも、既存エージェントの設計が制約に縛られているという話で、その結論は自然に「だから新しく作る余地がある」に着地します。

だからこそ、唯一の計算が1世代前の価格で組まれていたことが効きます。悪意の話ではありません。**価格表は3か月で変わり、設計メモは変わらないからです。** 私が使った価格も3か月前のものです。この記事も同じ形で古くなります。

最後に1つ。文書は `rtk` について「こういうプロジェクトは理想としてはエージェントを助けるが、実際には助けない。理由はたぶん LLM がネイティブに理解しないから」と書いています。これは 81,413 star が付いていて昨日も更新されているプロジェクトへの評価としては強い。そして著者自身「My guess」と書いていて、測定は添えられていません。**同じ文書の中で、自分の計算には式を付け、他人のツールには推測を付けている。** ここは対称でないと思いました。

## 1つだけ持ち帰るなら

**他人のコスト計算を見たら、価格表の日付だけ確認してください。** 式が正しくても、単価が1世代前なら結論の強さが変わります。今回は 33% の優位が 12% になり、キャッシュ読みを入れて 5% になりました。33% なら設計を決められますが、5% では決められません。**式のバグより、単価の陳腐化のほうがずっと静かに効きます。**
