## こんなことありませんか

Claude Cowork や Claude Code を使い始めると、こういう画面が出ます。

```
● Bash(rm -rf node_modules)

Do you want to proceed?
❯ 1. Yes
  2. No
```

エンジニアなら一瞬で判断できます。でも初めて見た人には、**危険なのか安全なのかまったく分かりません**。

そして分からないと、こうなります。

| 起きること | 結果 |
| --- | --- |
| 怖いので毎回止める | AI が使えず手作業に戻る |
| 分からないまま Yes を押す | いつか大事なファイルが消える |

どちらも避けたい。この記事は、**その判断ができるようになるための最小セット**です。

プログラミングの知識は要りません。10個だけ覚えてください。

---

## その1: 見るだけ / 変える

**最初に覚えるべきは、用語ではなくこの区別です。**

![命令を「見るだけ」の籠と「変える」鍵付きの箱に仕分ける](/images/claude-code-words-for-beginners/06-look-or-change.png)

これだけで、判断の8割が終わります。以降の用語は、この区別をつけるための道具です。

---

## その2: ディレクトリ = フォルダ

**まったく同じ意味**です。エンジニアが言い換えているだけ。頭の中で「フォルダ」に置き換えて読めば済みます。

---

## その3: パス = ファイルの住所

```
documents/2026/07/請求書.xlsx
```

`/` は**フォルダの区切り**です。「documents フォルダ → 2026 → 07 → 請求書.xlsx」と読みます。

`.` は「今いるフォルダ」、`..` は「1つ上」、`~` は「自分のホームフォルダ」。この3つだけ覚えれば、パスは読めます。

---

## その4: `ls` = 一覧を見る

フォルダの中身を並べるだけ。**何も変わりません。**🟢

同じ仲間（全部「見るだけ」なので安全）：

| コマンド | 意味 |
| --- | --- |
| `ls` | 一覧 |
| `pwd` | 今どこにいるか |
| `cat` | ファイルの中身を見る |
| `head` / `tail` | 先頭だけ / 末尾だけ見る |
| `wc` | 数える |

---

## その5: `grep` = Ctrl+F（検索）

```
grep -rn "請求書" ./documents
```

「documents フォルダの中から『請求書』を含む行を探す」という意味です。**Excel の検索と同じもの**で、何も変わりません。🟢

`rg` という表示も出ますが、**同じ「検索」**です（速い版）。`find` は「中身」ではなく「ファイル名」で探すもの。どれも安全です。

---

## その6: `rm` = 完全に削除（ゴミ箱に入らない）

ここからが本題です。

```
rm -rf node_modules
```

`-rf` は「**フォルダごと、確認なしで、強制的に消す**」という意味です。

:::message alert
`rm -rf` を見たら必ず立ち止まってください。ただし **`-rf` 自体が悪いのではなく、対象がなんであるかが全て**です。

- `rm -rf node_modules` → 取り寄せた部品。消しても入れ直せる 🟢
- `rm -rf documents` → **書類フォルダ。絶対に止める** 🔴
:::

![同じ重りでも、部品側はバネで戻り、書類側は穴に落ちて戻らない](/images/claude-code-words-for-beginners/07-same-weight.png)

---

## その7: `git commit` = セーブポイント

ゲームのセーブと同じです。**コミットしておけば、その時点に丸ごと戻せます。**

逆に言うと、**コミットしていない変更は戻せません**。

:::message
**作業を頼む前にコミット**。これが一番効く保険です。一言頼めば済みます。

```
作業を始める前に、今の状態をコミットして
```
:::

---

## その8: `diff` = 変更前後の違い

Word の「変更履歴の表示」と同じものです。

```diff
- 請求書の締め日は月末です
+ 請求書の締め日は毎月25日です
```

`-`（赤）が削除、`+`（緑）が追加。**AI が何を変えたか確認する一番速い方法**です。

---

## その9: `git push` = 外部に送る

**インターネット上（GitHub など）に送信する**操作です。送った後は「なかったこと」にしづらい。

社内資料や顧客情報が混ざったまま送ると**情報が外に出ます**。🔴

同じ「外に出る」仲間：デプロイ、本番反映、`--prod`。全部止めて確認する対象です。

---

## その10: `.env` = パスワードが入ったファイル

`.env` や鍵ファイル（`~/.ssh` の中）には、**パスワードや API キーが平文で入っています**。

AI に開かせると**会話の記録に残ります**。🔴

:::message
最初に一度だけ設定しておけば、以降は自動で守られます。

Cowork なら「設定 > Cowork」の Global instructions に、Claude Code ならプロジェクトの `CLAUDE.md` に：

```
- .env や鍵ファイルは開かない・中身を出力しない
- ファイルを削除・上書きする前に必ず確認する
- 元のファイルは書き換えず、新しいファイルとして作る
```
:::

---

## まとめ：この表だけで判断できます

| 見たら | 判断 |
| --- | --- |
| `ls` `pwd` `cat` `grep` `rg` `find` `git status` `git diff` | 🟢 **Yes** |
| `mkdir` `cp` `git add` `git commit` `npm install` | 🟢 Yes（増えるだけ） |
| `mv` `>` `chmod` | 🟡 対象を確認 |
| `rm -rf` `git reset --hard` `git push` `sudo` `deploy` `DROP` | 🔴 **止める** |

そして、**分からないときの正解はいつも同じ**です。

:::message
```
それは実行しないで。まず何をするコマンドか、
何が消えるかを日本語で説明して
```
:::

![機械を一旦止め、質問の紙を差し込んで答えを受け取る](/images/claude-code-words-for-beginners/08-ask-back.png)

**聞き返すことは作業の遅れではなく、正しい使い方です。** Claude は聞き返されることを前提に作られています。

## もっと詳しく — 読者によって続きが2冊あります

この記事は最小セットです。続きは**あなたがどちらを使うか**で分かれます。

### ターミナル（黒い画面）を使わない人

📘 **『AIが何をしているか分かる本 — 事務職のための Claude Cowork 入門』**

- Claude Desktop のインストールから Cowork を動かすまでの5ステップ
- フォルダの分け方（**フォルダ設計がそのままセキュリティ対策になる**話）
- プロジェクト機能と、指示の書き分け（Global / プロジェクト / フォルダ）
- **承認画面の言葉**（Read/Write、削除保護、プロンプトインジェクション）
- 止めるべきサインと、事故ったときの復旧

:::message
実は Anthropic 公式は「**タスクを監視せよ。コマンドを監視するのではない**（Monitor tasks, not just commands）」「一つ一つのコマンドを検証しようとすべきではない」と書いています。

つまり Cowork で事務作業をするだけなら、**この記事のコマンドすら覚えなくていい**のです。詳しくはそちらの本で扱いました。
:::

### ターミナルで Claude Code を触る人

📘 **『黒い画面が読めるようになる本 — Claude Code コマンド・用語辞典』**

- ターミナルと Git の言葉
- 見るだけのコマンド／変えるコマンド（オプション付きの一覧）
- 画面表示（`● Read(...)` `● Bash(...)`）の読み方
- 記号（`-rf` `~` `*` `|` `>`）とエラー文（`command not found` など）の逆引き
