前の章で見たとおり、**一つ一つのコマンドを検証する必要はありません**。公式もそう言っています。

ただし画面に英語が流れると、それだけで不安になります。この章は**その不安を消すための1ページ**です。覚える必要はありません。**見えたときにここへ戻ってきてください。**

:::message
**この章の使い方**

読むのは1回だけで構いません。**この表の左側にあるものが出ていたら、それは無害です。** 右側のものが出ていたら、承認画面が出るはずなので、そのとき内容を読んでください。
:::

## 一目でわかる対応表

![3本の紐。ほどける蝶結び、絡んだ結び目、切れて床に落ちた紐](/images/claude-code-words-for-office/16-three-cords.png)

| 🟢 見えても無視していい（何も変わらない） | 意味 |
| --- | --- |
| `ls` | フォルダの中を一覧した |
| `pwd` `cd` | 今いる場所を確認した・移動した |
| `cat` `head` `tail` | ファイルを開いて読んだ |
| `grep` `rg` | 文字を検索した（Excel の Ctrl+F と同じ） |
| `find` `glob` | ファイル名で探した |
| `wc` | 件数や行数を数えた |
| `git status` `git diff` `git log` | 何が変わったかを確認した |

**上の表のものは、ファイルを1つも変えません。** 流れていても放っておいて大丈夫です。

| 🟡 増えるだけ（元は残る） | 意味 |
| --- | --- |
| `mkdir` | フォルダを作った |
| `cp` | コピーを作った（**元は残る**） |
| `touch` | 空のファイルを作った |
| `git add` `git commit` | 作業内容を保存した（**むしろ安全側**） |
| `npm install` `pip install` | 必要な部品を取り寄せた |

| 🔴 承認画面が出たら必ず読む | 意味 |
| --- | --- |
| `rm` `rm -rf` | **削除。ゴミ箱に入らない** |
| `mv` | 移動（**元の場所からは消える**） |
| `>` | 上書き（**元の中身が消える**） |
| `git push` | **外部（インターネット）に送信** |
| `git reset --hard` | 保存前の作業を捨てて巻き戻す |
| `sudo` | 管理者権限で実行 |
| `curl -d` `curl -X POST` | **外部にデータを送信** |
| `DROP` `DELETE FROM` | **データベースのデータを削除** |
| `deploy` `--prod` | **本番環境に反映**（お客様に見える） |

## 記号だけ3つ覚える

コマンド名より、この3つの記号のほうが実用的です。

| 記号 | 意味 | 危険度 |
| --- | --- | --- |
| **`-rf`** | 「フォルダごと、確認なしで、強制的に」 | 🔴 見たら止まる |
| **`>`** | 上書き（元の中身が消える） | 🔴 |
| **`>>`** | 追記（元の中身は残る） | 🟡 |

:::message alert
**`-rf` は対象がすべてです。**

- `rm -rf node_modules` → 取り寄せた部品。消しても入れ直せる 🟢
- `rm -rf 契約書` → **書類フォルダ。絶対に止める** 🔴

`-rf` そのものが悪いのではなく、**その後ろに何が書いてあるか**だけが問題です。
:::

## 迷ったときの一言（これだけ覚える）

コマンドを読む代わりに、日本語で聞き返せます。

:::message
```
それは実行しないで。まず何をするコマンドか、
何が消えるかを日本語で説明して
```
:::

**聞き返すことは作業の遅れではなく、正しい使い方です。**

もっと安全にしたい場合は、削除の予定を先に出させます。

```
消す前に、消える予定のファイル一覧だけ表示して
```

この章は意図的に**1ページに圧縮**しています。コマンドを本格的に読めるようになりたい場合は、姉妹編があります。
