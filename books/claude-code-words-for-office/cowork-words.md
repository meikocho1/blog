title: "第1部 Cowork の画面に出てくる言葉"
free: true
---

Cowork を使っていると出てくるカタカナ語・英語です。**ターミナルや Git の言葉は出てきません**（事務作業では使わないので、姉妹編に分けました）。

ここにあるのは**実際に画面で見る言葉だけ**です。

---

## プロンプト（Prompt）

**一言でいうと**: AI への指示文。あなたが打ち込む日本語の文章そのもの。

「プロンプトを工夫する」＝「**頼み方を工夫する**」という意味です。呪文でも専門技術でもありません。

---

## コンテキスト（Context）

**一言でいうと**: AI が今おぼえている情報の全体。会話の履歴＋読んだファイルの中身。

AI の**短期記憶**だと考えてください。ここに入っていない情報について、AI は知りません。

## コンテキストウィンドウ（Context Window）

**一言でいうと**: その短期記憶の上限サイズ。

![小さすぎる机に紙を足し続け、古い紙が端から床に落ちていく](/images/claude-code-words-for-office/13-desk-overflow.png)

机の広さのようなものです。書類を広げすぎると、古い書類が机から落ちます。**長く会話を続けると、最初のほうの内容が押し出されて忘れられます。**

人間の「うっかり忘れる」とは違い、**入る枠に上限がある**のが原因です。だから「さっき言ったのに」が起きます。

---

## セッション（Session）

**一言でいうと**: AI との1回の作業のかたまり。

セッションを新しくすると、コンテキスト（短期記憶）は空になります。

![詰まった机から一枚だけ持って、空の新しい机へ移る](/images/claude-code-words-for-office/21-new-desk.png)

:::message
**うまく動かなくなったときの最初の対処法は、新しいセッションで頼み直すことです。**

机を片付けるのと同じで、これだけで直る場合がかなりあります。「AIが壊れた」のではなく「机が散らかった」だけ、というケースが多いのです。
:::

Cowork のセッションは Anthropic のサーバー上で動くので、**ノートパソコンを閉じても作業は続きます**。ただしあなたのパソコンの中のファイルを触る作業のときは、デスクトップアプリを開いたままにしておく必要があります。

---

## トークン（Token）

**一言でいうと**: AI の利用量を数える単位。文字数のようなもの。

だいたい**日本語1文字 ≒ 1トークン弱**です。「トークンを消費する」＝「**AI の利用枠を使っている**」という意味です。

:::message
**Cowork は普通のチャットより多くのトークンを使います。** 公式にも明記されています。複雑で長い作業だからです。

上限に当たりやすい人は、簡単な質問は Chat（普通の会話）で済ませてください。
:::

---

## モデル（Model）

**一言でいうと**: AI の頭脳の種類。名前とバージョンがある。

Opus、Sonnet、Haiku などの種類があります。ざっくり「賢いが遅い／バランス型／速くて安い」の違いです。**事務作業では既定のままで問題ありません。**

---

## エージェント（Agent）

**一言でいうと**: 自分で考えて手を動かす AI。答えるだけでなく**作業する** AI。

チャットの AI は「答えを返す」だけですが、エージェントは「**ファイルを開く → 直す → 確認する**」を自分で順番にやります。Cowork はエージェントです。

だから許可を求めてくるわけです。**手を動かす相手だから**です。

## サブエージェント（Sub-agent）

**一言でいうと**: 大きな作業を分担するために AI が呼び出す、AI の手下。

公式には「Claude は複雑な作業を小さなタスクに分解し、**並行する作業の流れを調整する**」と書かれています。画面で複数の作業が同時に進んでいるように見えるのはこれです。

異常ではありません。

---

## ツール（Tool）

**一言でいうと**: AI が使える道具。ファイルを読む、コマンドを実行する、などの機能。

公式は道具を2種類に分けています。**この2分類が判断の軸になります**（詳しくは次章）。

| 分類 | 意味 |
| --- | --- |
| **Read tools** | 読むだけ |
| **Write tools** | 実際に**行動する**（作る・消す・送る・クリックする） |

---

## Global instructions（グローバル指示）

**一言でいうと**: 全ての作業に効く、あなた専用のルールブック。

![機械の入口に本を立てておくと、機械が自分でページをめくって読む](/images/claude-code-words-for-office/22-rulebook-at-the-door.png)

**設定 > Cowork** から設定します。「日本語で説明して」「元のファイルは書き換えないで」といった**毎回言いたくないこと**を書いておくと、以降は自動で効きます。

:::message
**これが一番コスパのいい設定です。** 一度書けば、毎回のお願いが省略できます。おすすめの内容は準備編に載せました。
:::

## プロジェクトの指示 / フォルダの指示

**一言でいうと**: 案件ごと・フォルダごとに効く、範囲を限定したルール。

3種類あって混乱しやすいので、対応表だけ置いておきます。

| 場所 | 効く範囲 |
| --- | --- |
| Global instructions | **すべての作業** |
| プロジェクトの指示 | その案件だけ |
| フォルダの指示 | そのフォルダだけ |

迷ったら **Global に書く**のが実用的です。

---

## Skill（スキル）

**一言でいうと**: AI に覚えさせた作業手順書。

「請求書の処理手順」のような決まった作業を文書にしておくと、AI が必要なときに読んで、その手順どおりに動きます。**マニュアルを渡しておく**のと同じ発想です。

---

## フォルダ / ディレクトリ（Directory）

**一言でいうと**: 同じものです。「ディレクトリ」は「フォルダ」の言い換え。

技術文書では「ディレクトリ」と書かれることが多いですが、**頭の中で「フォルダ」に置き換えて読めば済みます**。

## パス（Path）

**一言でいうと**: ファイルの住所。どのフォルダのどのファイルかを表す文字列。

```
書類/2026/07/請求書.xlsx
```

![入れ子になった3つの箱。蓋を1つずつ通って一番奥の紙に届く](/images/claude-code-words-for-office/23-nested-boxes.png)

`/`（スラッシュ）は**フォルダの区切り**です。上の例は「書類 → 2026 → 07 → 請求書.xlsx」と読みます。

覚えるのはこの3つだけで足ります。

| 記号 | 意味 |
| --- | --- |
| `/` | フォルダの区切り |
| `..` | 1つ上のフォルダ |
| `~` | 自分のホームフォルダ |

:::message alert
**`~` で始まるパスが出てきたら注意してください。** それは作業フォルダの外を指しています。なぜそこを触るのか確認する価値があります。
:::

---

## 認証情報ファイル（`.env` / 鍵ファイル）

**一言でいうと**: パスワードや API キーが、そのまま文字で書かれているファイル。

![封をされた封筒に鍵。伸びてくる腕を手で止め、記録は空白のまま](/images/claude-code-words-for-office/24-sealed-envelope.png)

`.env`（ドットイーエヌブイ）や `~/.ssh` の中身が代表例です。

:::message alert
**AI に開かせないでください。**

理由は「信用していないから」ではありません。**一度開いて読み上げると、その内容が作業の記録に残ってしまう**からです。記録は後から消せません。

Global instructions にこう書いておけば、以降は自動で守られます。

```
.env や鍵ファイルは開かない・中身を出力しない
```
:::

---

## 成果物（Artifact / 出力）

**一言でいうと**: AI が作って渡してくるファイル。

Cowork は「見た目の整った完成品」を作れます。公式に挙げられているものだけでも:

- **数式が動く Excel**（VLOOKUP、条件付き書式、複数シート付き）
- **PowerPoint のスライド**（メモや議事録から）
- **体裁の整った文書**（音声メモや散らばったメモから）

作業が終わると、セッション上でプレビューして保存できます。**どこに保存されたか分からなくなったら、そのまま「どこに保存した？」と聞けます。**

---

## エラー（Error）

**一言でいうと**: 失敗の通知。**「壊れた」という意味ではありません。**

「できませんでした」という報告です。赤い文字が出ても慌てなくて大丈夫で、多くは場所の間違いや一時的な不調です。

**対処法は1つだけです。**

```
このエラーが出ました。原因と対処を日本語で説明して、
危険な操作を含まない範囲で直してください。

（エラー文を全部そのまま貼る）
```

:::message
**「危険な操作を含まない範囲で」の一文が効きます。** これがないと、AI が手っ取り早く削除などを提案してくることがあります。
:::

---

## この章のまとめ

| 覚えること | 実用的な意味 |
| --- | --- |
| コンテキストには上限がある | 長い作業は忘れる。**新セッションで直る** |
| Cowork はエージェント | 手を動かすので許可を聞いてくる |
| 道具は **Read と Write** の2種類 | これが判断の軸（次章） |
| Global instructions | 毎回言いたくないことはここに1回書く |
| `~` で始まるパス | 作業フォルダの外。理由を確認 |
| `.env` は開かせない | 記録に残ると消せない |
| エラーは「失敗の報告」 | 全文コピーして貼れば足りる |

次の章が本題です。**承認を求められたときに何を見るか**を扱います。
