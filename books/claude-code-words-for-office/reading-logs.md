この章がこの本の本題です。**画面に流れていく表示を読めるようにします。**

用語もコマンドも、結局はここで使うためのものです。逆に言えば、**この章の読み方さえ身につけば、知らない単語が出てきても落ち着いて対応できます**。

---

## 表示は「誰が・何を・どうした」の3点セット

:::message
この章の表示例は **Claude Code（ターミナル）** のものです。**Cowork では同じ内容がもっと読みやすい形**（進捗表示やカードなど）で出ますが、**「どの道具で・何に対して・どうなったか」という構造は同じ**です。読み方はそのまま通用します。
:::

Claude Code の作業ログは、だいたいこの形です。

```
● Read(documents/請求書テンプレート.md)
  ⎿  Read 120 lines
```

分解するとこうなります。

| 部分 | 意味 |
| --- | --- |
| `●` | AI が1つの作業をした、という印 |
| `Read` | **使った道具**（何をしたか） |
| `(documents/...)` | **対象**（どのファイルに対して） |
| `⎿` の行 | **結果**（どうなったか） |

![3つの丸窓に道具・対象・結果が順に映り、真ん中を指差す](/images/claude-code-words-for-office/11-three-windows.png)

つまり読む順番は決まっています。

:::message
**① 道具の名前を見る → ② カッコの中の対象を見る → ③ 結果を見る**

この3ステップだけです。
:::

:::message
表示の細かい書式（記号や英語の言い回し）は Claude Code のバージョンによって変わります。**「道具・対象・結果」の3点セットという構造は変わりません**ので、そこを見てください。
:::

---

## 道具の名前の一覧

カッコの前に出てくる英単語が「道具」です。これだけ覚えれば十分です。

| 表示 | 意味 | 変わる？ |
| --- | --- | --- |
| `Read` | ファイルを**読んだ** | 変わらない 🟢 |
| `Search` / `Grep` / `Glob` | ファイルを**探した** | 変わらない 🟢 |
| `Bash` | **コマンドを実行した** | 中身次第 ⚠️ |
| `Write` | ファイルを**新しく書いた** | 変わる 🟡 |
| `Edit` / `Update` | ファイルを**書き換えた** | 変わる 🟡 |
| `WebFetch` / `WebSearch` | **インターネットを見た** | 変わらない 🟢 |
| `Task` / `Agent` | **別の AI に作業を任せた** | 中身次第 ⚠️ |
| `TodoWrite` | **作業リストを更新した** | 変わらない 🟢 |

**`Read` `Search` が並んでいる間は、AI は調べているだけ**です。ここは眺めなくて構いません。

注目すべきは `Edit` `Write` `Bash` の3つだけです。

## 実例で読んでみる

### 例1: 調べているだけ

```
● Search(pattern: "締め日", path: "documents")
  ⎿  Found 3 files

● Read(documents/2026-07.md)
  ⎿  Read 45 lines
```

**読み方**: 「documents フォルダから『締め日』を探して3件見つけ、そのうち1つを開いて読んだ」

**判断**: 🟢 何も変わっていません。放っておいて大丈夫です。

### 例2: ファイルを書き換えた

```
● Edit(documents/2026-07.md)
  ⎿  Updated documents/2026-07.md with 2 additions and 1 removal
```

**読み方**: 「2026-07.md を書き換えた。2行追加、1行削除」

**判断**: 🟡 変わりました。**何が変わったのか確認する価値があります。**

確認方法は日本語で頼めます。

```
今の変更の diff を見せて
```

### 例3: コマンドを実行した

```
● Bash(rm -rf node_modules)
  ⎿  (No content)
```

**読み方**: 「node_modules フォルダを中身ごと削除した」

**判断**: 対象が `node_modules`（取り寄せた部品）なので、入れ直せます。問題ありません。
もし対象が `documents` だったら大問題です。**`Bash` は中身を必ず見てください。**

### 例4: エラーが出た

```
● Bash(npm test)
  ⎿  Error: 3 tests failed
```

**読み方**: 「テストを実行したら3件失敗した」

**判断**: 🟢 **壊れたのではなく、失敗が報告されただけ**です。AI はこの後たいてい自分で直しに行きます。慌てなくて大丈夫です。

## 許可を求められたときの画面

`Bash` などで確認が必要な操作の前には、こういう確認が出ます（文言はバージョンで変わります）。

```
Bash command
  rm -rf documents/古い資料

  Delete the 古い資料 folder

Do you want to proceed?
❯ 1. Yes
  2. Yes, and don't ask again for rm commands
  3. No, and tell Claude what to do differently (esc)
```

選択肢の意味はこうです。

| 選択肢 | 意味 | 使いどき |
| --- | --- | --- |
| **1. Yes** | 今回だけ許可 | 内容を確認して納得できたとき |
| **2. Yes, and don't ask again** | **今後この種類は聞かない** | 安全なコマンド（`ls` など）だけ |
| **3. No, and tell Claude...** | 断って、代わりの指示を出す | **迷ったときは常にこれ** |

:::message alert
**2番（今後聞かない）は、`rm` や `push` に対しては絶対に選ばないでください。** 一度選ぶと、以降その種類の操作が確認なしで実行されます。安全なのは `ls` `pwd` `git status` のような「見るだけ」のコマンドに限ります。
:::

3番を選んだ場合、そのまま日本語で理由を書けます。

```
それは消さないで。まず中身の一覧だけ見せて
```

## 長い作業の後に確認する3つの質問

AI が長時間作業した後、ログを全部読み返す必要はありません。**この3つを日本語で聞けば足ります。**

```
1) 何を変えましたか？変更したファイルの一覧を出して
2) その変更の diff を見せて
3) 消したファイルはありますか？あれば理由も
```

3つ目が特に重要です。**追加や修正より、削除のほうが取り返しがつきません。**

## この章のまとめ

| 覚えること |
| --- |
| 表示は「**道具・対象・結果**」の3点セット |
| `Read` `Search` は無視してよい。見るべきは `Edit` `Write` `Bash` |
| `Bash` は**カッコの中身**が全て |
| エラー表示は「壊れた」ではなく「失敗の報告」 |
| 「今後聞かない」は**見るだけのコマンドにしか使わない** |
| 迷ったら 3番（No）→ 日本語で理由を書く |

次の章では、この判断を**フローチャート1枚**にまとめます。
