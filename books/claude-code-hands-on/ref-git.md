### 🟢 `git status`（ギット ステータス）

**見るだけ・安全**

**一言でいうと**: いま何を変えたかを一覧で見せるだけの確認コマンド

変更したファイル、保存予定に入れたファイル、まだ入れていないファイルを分けて表示します。机の上を見渡して「書きかけの書類はどれか」を確認する作業と同じです。表示するだけで何も変えないので、取り消す必要はありません。何が起きているか分からなくなったら、まずこれを打つのが一番安全です。

```
git status
→ Changes not staged for commit:
     modified:   README.md
```

| オプション | 意味 |
| --- | --- |
| `-s` | 1ファイル1行の短い形式で表示する |
| `-sb` | 短い形式＋今いるブランチ名も表示する |

### 🟢 `git diff`（ギット ディフ）

**見るだけ・安全**

**一言でいうと**: 変更の前と後を行単位で見比べる差分の表示コマンド

追加した行の先頭に + 、消した行の先頭に - が付いて出てきます。文書の校正で「赤入れ前」と「赤入れ後」を並べて見るのと同じです。見るだけなのでファイルは変わらず、取り消しも不要です。何も表示されないときは「変更がない」という意味です。

```
git diff
→ -古い行
   +新しい行
```

| オプション | 意味 |
| --- | --- |
| `--staged` | すでに保存予定に載せた分の差分を見る |
| `--stat` | 中身は出さず、ファイルごとの増減行数だけ見る |

### 🟢 `git log`（ギット ログ）

**見るだけ・安全**

**一言でいうと**: 過去のコミット（保存の記録）を新しい順に並べて見る

いつ・誰が・どんな説明を付けて保存したかが、新しいものから順に出てきます。銀行の通帳を上からめくって取引履歴を見るのと同じ感覚です。読むだけなので何も壊れず、取り消しも不要です。長い出力は q キーで閉じられます。

```
git log --oneline
→ aa5dcfd chore: initialize project
```

| オプション | 意味 |
| --- | --- |
| `--oneline` | 1コミット1行にまとめて読みやすくする |
| `-5` | 直近5件だけ表示する |
| `--graph` | 枝分かれを線の図で表示する |

### 🟢 `git show`（ギット ショー）

**見るだけ・安全**

**一言でいうと**: 指定した1件のコミットの中身と差分をまとめて見る

コミットの説明文と、そのとき実際に何行変わったかを一度に表示します。通帳の1行をタップして明細を開くのと同じです。何も指定しないと直前のコミットを見せます。見るだけなので取り消しは不要です。

```
git show aa5dcfd
```

| オプション | 意味 |
| --- | --- |
| `--stat` | 差分の中身は省き、変わったファイル名だけ見る |

### 🟡 `git add`（ギット アド）

**変わるが戻せる**

**一言でいうと**: 次のコミットに含める変更を選んで台に載せる操作

変更したファイルのうち「今回保存する分」だけを、レジのベルトコンベアに載せるように選ぶ操作です。まだ履歴には残らず、載せただけの状態です。載せ間違えても git restore --staged で降ろせるので、取り消せます。ファイルの中身自体は変わりません。

```
git add README.md
```

| オプション | 意味 |
| --- | --- |
| `.` | 今のフォルダ以下の変更を全部載せる |
| `-A` | 削除も含めて全部載せる |
| `-p` | 変更を一部分ずつ選びながら載せる |

### 🟡 `git commit`（ギット コミット）

**変わるが戻せる**

**一言でいうと**: 選んだ変更に名前を付けて履歴に1件保存する操作

台に載せた変更をまとめて、説明文を添えて履歴に記録します。書類を1つの封筒にまとめ、表に「表紙の修正」と書いてファイルに綴じる作業です。直後なら git reset --soft HEAD~1 でコミットだけ取り消せる（中身は残る）ので、取り消せます。説明文を書き忘れるとエディタが開きます。

```
git commit -m "fix: 表示のずれを直した"
→ 1 file changed, 3 insertions(+)
```

| オプション | 意味 |
| --- | --- |
| `-m "説明"` | 説明文をその場で指定する（エディタが開かない） |
| `-a` | add を省略して、変更済みファイルをまとめて保存する |
| `--amend` | 新しく作らず、直前のコミットを作り直す |

### 🟡 `git commit --amend`（ギット コミット アメンド）

**変わるが戻せる**

**一言でいうと**: 直前のコミットを作り直してメッセージや中身を直す

新しい記録を増やさず、さっき書いた封筒の表書きや中身を差し替えます。出したばかりの手紙をポストから抜いて書き直すイメージです。手元だけなら git reflog から元に戻せるので取り消せますが、すでに push（送信）済みだと強制上書きが必要になり危険度が跳ね上がります。送信前に使うのが原則です。

```
git commit --amend -m "fix: 説明文を書き直した"
```

| オプション | 意味 |
| --- | --- |
| `--no-edit` | メッセージは変えず中身だけ差し替える |

### 🟡 `git branch`（ギット ブランチ）

**変わるが戻せる**

**一言でいうと**: 作業の枝を一覧・作成・削除する。既定は一覧表示

何も付けずに打つと、今あるブランチ（作業の枝）の一覧と、自分がいる枝に * が付いて出ます。本を書くときの「章ごとの下書きコピー」の管理表のようなものです。一覧表示は見るだけで安全、作成も取り消せます。-d の削除も、消した枝の中身は git reflog から拾えることが多いですが、-D（大文字）は未合流の作業ごと消すので慎重に。

```
git branch
→ * main
     feature/login
```

| オプション | 意味 |
| --- | --- |
| `-a` | ネット側の枝も含めて全部一覧する |
| `-d 名前` | 合流済みの枝を削除する（未合流なら止まる） |
| `-D 名前` | 合流していなくても強制的に削除する |
| `-m 新名前` | 今いる枝の名前を変える |

### 🟡 `git switch`（ギット スイッチ）

**変わるが戻せる**

**一言でいうと**: 別のブランチ（作業の枝）に乗り換えるコマンド

手元のファイルの中身が、指定した枝の状態にまるごと入れ替わります。同じ机で「A社の案件フォルダ」から「B社の案件フォルダ」に持ち替えるイメージです。元の枝名でもう一度打てば戻れるので、取り消せます。ただし保存していない編集があると、そのままでは乗り換えを断られることがあります（先に commit か stash を）。

```
git switch main
→ Switched to branch 'main'
```

| オプション | 意味 |
| --- | --- |
| `-c 新名前` | 新しい枝を作って、そこへ乗り換える |
| `-` | 直前にいた枝へ戻る |
| `--detach` | 枝ではなく特定のコミットに直接立つ（デタッチHEAD） |

### 🟡 `git checkout`（ギット チェックアウト）

**変わるが戻せる**

**一言でいうと**: 昔からある乗り換え兼ファイル復元の万能コマンド

枝の乗り換えと、ファイルを保存済みの状態に戻す作業の両方を兼ねる古いコマンドです。今は役割ごとに git switch（乗り換え）と git restore（復元）に分かれたので、新しく覚えるならそちらが安全です。乗り換えなら取り消せますが、ファイル名を付けた形（git checkout -- ファイル名）は書きかけの編集を捨てる操作で、これは取り消せません。画面でこの形を見たら手を止めてください。

```
git checkout main
→ Switched to branch 'main'
```

| オプション | 意味 |
| --- | --- |
| `-b 新名前` | 新しい枝を作って乗り換える（switch -c と同じ） |
| `-- ファイル名` | そのファイルの編集を捨てて戻す（取り消せない） |

### 🟡 `git merge`（ギット マージ）

**変わるが戻せる**

**一言でいうと**: 別のブランチの変更を今の枝に合流させるコマンド

別の枝で進めた作業を、今いる枝に取り込んで1つにまとめます。2人が別々に直した企画書を1つに合わせる作業です。同じ場所を両方が直しているとコンフリクト（衝突）になり、手で選ぶ必要があります。合流の途中なら git merge --abort で完全に取り消せ、終わった後も git reflog を使えば戻せます。

```
git merge feature/login
→ CONFLICT (content): Merge conflict in app.js
```

| オプション | 意味 |
| --- | --- |
| `--abort` | 合流を中止して、始める前の状態に戻す |
| `--no-ff` | 合流したという記録を必ず1件残す |

### 🟡 `git rebase`（ギット リベース）

**変わるが戻せる**

**一言でいうと**: 枝の付け根を移して履歴を一直線に作り直す操作

自分の作業を、最新の本線の上に載せ替えて、履歴を枝分かれのない一本道に整えます。付箋を貼り替えて順番を組み直すような作業で、コミットは中身が同じでも「別物」に作り替えられます。途中なら git rebase --abort で戻せ、終わった後も git reflog から復帰できます。ただし他人と共有済みの枝でやると相手の履歴と食い違うため、共有後は触らないのが原則です。

```
git rebase main
→ Successfully rebased and updated refs/heads/feature.
```

| オプション | 意味 |
| --- | --- |
| `--abort` | 作り直しを中止して元の状態に戻す |
| `--continue` | 衝突を直した後、続きを進める |
| `-i` | どのコミットをどうするか対話的に選ぶ |

### 🟡 `git stash`（ギット スタッシュ）

**変わるが戻せる**

**一言でいうと**: 書きかけの変更を一時的に棚へ預けて机を空ける

まだコミットしたくない編集を丸ごと預かってもらい、手元を保存直後のきれいな状態に戻します。急な来客のとき、机の書類を一式引き出しにしまうのと同じです。git stash pop で取り出せるので取り消せます。ただし Git がまだ知らない新規ファイルは既定では預かってくれないので、含めるには -u が必要です。

```
git stash
→ Saved working directory and index state WIP on main
```

| オプション | 意味 |
| --- | --- |
| `-u` | 新規作成したまだ未管理のファイルも一緒に預ける |
| `-m "説明"` | どの作業を預けたか名前を付ける |

### 🟡 `git stash pop`（ギット スタッシュ ポップ）

**変わるが戻せる**

**一言でいうと**: 棚に預けた変更を取り出して戻す。棚からは消える

最後に預けた編集を手元に戻し、棚の控えは削除されます。引き出しから書類を出して机に広げ直す作業です。不安なときは、控えを残す git stash apply を使って、うまく戻ったのを確認してから消す方が安全です。取り出し先が変わっていると衝突することがあります。

```
git stash pop
→ Dropped refs/stash@{0}
```

| オプション | 意味 |
| --- | --- |
| `stash@{1}` | 何番目の預かり分を取り出すか指定する |

### 🟢 `git stash list`（ギット スタッシュ リスト）

**見るだけ・安全**

**一言でいうと**: 棚に預けてある変更の一覧を見るだけのコマンド

預けた編集が新しい順に stash@{0}、stash@{1} という名前で並びます。引き出しの中身の目録を見るのと同じです。見るだけなので何も変わらず、取り消しも不要です。預けたまま忘れがちなので、ときどき確認すると安心です。

```
git stash list
→ stash@{0}: WIP on main: aa5dcfd chore: init
```

### 🟡 `git reset --soft`（ギット リセット ソフト）

**変わるが戻せる**

**一言でいうと**: コミットだけ取り消し、変更は台に載せたまま残す

公式ドキュメントの言葉どおり、手元のファイルも保存予定の台も一切触らず、履歴の位置だけを戻します。封筒に綴じたのを解いて、中の書類はそのまま台に戻すイメージです。ファイルは無傷なので、そのまま commit し直せます。取り消しも git reflog から可能で、3種類の reset の中でいちばん安全です。

```
git reset --soft HEAD~1
```

| オプション | 意味 |
| --- | --- |
| `HEAD~1` | 1つ前のコミットまで戻す（数字を変えれば件数も変わる） |

### 🟡 `git reset --mixed`（ギット リセット ミックスド）

**変わるが戻せる**

**一言でいうと**: コミットと台に載せた状態を取り消す。ファイルは残る

オプションを付けずに git reset と打ったときの既定の動きです。履歴の位置と「保存予定の台」を戻し、手元のファイルの中身はそのまま残します。台に載せた書類を全部降ろすだけで、書いた内容は消えません。ファイルが無事なので取り消せます。

```
git reset HEAD~1
→ Unstaged changes after reset:
     M  README.md
```

| オプション | 意味 |
| --- | --- |
| `HEAD` | コミットは触らず、台に載せた分だけ全部降ろす |

### 🔴 `git reset --hard`（ギット リセット ハード）

**止めて確認**

**一言でいうと**: 指定地点までファイルごと巻き戻す。保存前の作業は消える

公式ドキュメントに「すべてのファイルとフォルダを指定コミットの版で上書きし、未管理のファイルも上書きしうる」と明記された操作です。まだコミットしていない編集は消え、原則として取り戻せません。書きかけの原稿を保存せずに閉じるのと同じで、ゴミ箱にも残りません。この文字列を画面で見たら必ず手を止めて、人に確認してください。

```
git reset --hard HEAD~1
→ HEAD is now at aa5dcfd chore: initialize
```

| オプション | 意味 |
| --- | --- |
| `HEAD` | 今のコミットまで巻き戻す＝手元の編集を全部捨てる |
| `origin/main` | ネット側の状態に合わせて手元を丸ごと上書きする |

### 🟡 `git revert`（ギット リバート）

**変わるが戻せる**

**一言でいうと**: 過去のコミットを打ち消す新しいコミットを作る

履歴を消さず、「あれを元に戻した」という記録を新しく1件足す方法です。帳簿の間違いを消しゴムで消さず、赤で訂正の1行を追記するのと同じ考え方です。履歴が残るので他人と共有済みでも安全に使えます。さらに revert し直せば元に戻せるので、取り消せます。

```
git revert aa5dcfd
→ [main 1b2c3d4] Revert "chore: initialize"
```

| オプション | 意味 |
| --- | --- |
| `--no-commit` | 打ち消しを台に載せるだけで、まだ保存しない |
| `--abort` | 衝突して止まったとき、始める前に戻す |

### 🔴 `git restore`（ギット リストア）

**止めて確認**

**一言でいうと**: 編集を捨ててファイルを保存済みの状態に戻す

指定したファイルの書きかけの編集を破棄して、直前に保存した内容に戻します。上書き保存していない文書を保存せず閉じるのと同じで、失った編集は取り消せません。ただし --staged だけを付けた形は「台から降ろすだけ」で中身は消えないため、こちらは安全です。ファイル名だけを渡す形が出てきたら止めて確認してください。

```
git restore README.md   ← 編集が消える
git restore --staged README.md   ← 台から降ろすだけ
```

| オプション | 意味 |
| --- | --- |
| `--staged` | 台から降ろすだけ。ファイルの中身は消えない（安全） |
| `--source=HEAD~1` | どの時点の内容に戻すかを指定する |
| `.` | 今のフォルダ以下すべてを戻す（被害が広い） |

### 🔴 `git clean -fd`（ギット クリーン エフディー）

**止めて確認**

**一言でいうと**: Git が知らない新規ファイルやフォルダをまとめて削除

まだ一度も Git に登録していないファイルを、フォルダごと本当に削除します。Git が中身を控えていないため、履歴からも取り戻せず、取り消しは不可能です。まだ誰にも見せていない新しい書類を、確認せずシュレッダーにかけるのと同じです。まず -n を付けて「何が消えるか」だけ表示させ、それを人に見せて確認してください。

```
git clean -n   ← 消える予定を表示するだけ（安全）
→ Would remove memo.txt
```

| オプション | 意味 |
| --- | --- |
| `-n` | 消さずに、消える予定の一覧だけ表示する（安全） |
| `-f` | 実際に削除する（これが付くと本当に消える） |
| `-d` | フォルダごと削除の対象にする |
| `-x` | .gitignore で無視している分も含めて消す（最も被害が大きい） |

### 🔴 `git push`（ギット プッシュ）

**止めて確認**

**一言でいうと**: 手元のコミットをネット上の共有リポジトリへ送る

自分のパソコンにしかなかった記録を、GitHub などの共有場所へ送信します。書き上げた原稿を編集部にメール送信するのと同じで、送った瞬間から他人が見られる状態になります。送信自体は後から打ち消しコミットで直せますが、外に出た事実は消えません。公開・共有にあたる操作なので、実行前に必ず一言確認してください。

```
git push origin main
→ To github.com:user/repo.git
     aa5dcfd..1b2c3d4  main -> main
```

| オプション | 意味 |
| --- | --- |
| `-u origin main` | 送り先を覚えさせ、次回から git push だけで済むようにする |
| `--tags` | 目印（タグ）もまとめて送る |
| `--delete 枝名` | ネット側の枝を削除する（他人に影響するので要確認） |

### 🔴 `git push --force`（ギット プッシュ フォース）

**止めて確認**

**一言でいうと**: 相手側の履歴を上書きする強制送信。他人の作業が消える

公式ドキュメントが「リモートがコミットを失う原因になりうる」「他人が送った作業を上書きしうる」と警告している操作です。共有の棚にある皆の書類を、自分の版で丸ごと差し替えるのと同じで、消えた分は取り戻せないことがあります。どうしても必要なときは、他人の更新があれば失敗してくれる --force-with-lease を使います。-f という短い形も同じ意味なので、見たら必ず止めて確認してください。

```
git push --force-with-lease origin main   ← まだ安全側
```

| オプション | 意味 |
| --- | --- |
| `-f` | --force の短い書き方（同じ危険度） |
| `--force-with-lease` | 相手側に自分の知らない更新があれば失敗してくれる、より安全な版 |

### 🟡 `git pull`（ギット プル）

**変わるが戻せる**

**一言でいうと**: 共有リポジトリの最新を取ってきて今の枝に合流させる

ネット側の新しい変更を取得し、そのまま今の枝に合流させる 2 段階をまとめて行います。共有フォルダの最新版を落として、自分の手元の版と合わせる作業です。同じ箇所を両方が直していればコンフリクトになります。合流分は取り消せますが、書きかけの編集があると失敗しやすいので、先に commit か stash をしておくと安全です。

```
git pull
→ Fast-forward
     README.md | 2 +-
```

| オプション | 意味 |
| --- | --- |
| `--rebase` | 合流ではなく、自分の作業を最新の上に載せ替える |
| `--ff-only` | きれいに追いつける場合だけ実行し、無理なら何もしない（安全） |

### 🟢 `git fetch`（ギット フェッチ）

**見るだけ・安全**

**一言でいうと**: 最新情報を取ってくるだけ。手元のファイルは変えない

ネット側の状態を手元に取り込みますが、自分が編集中のファイルには一切触りません。共有フォルダの最新版を「見るだけ」ダウンロードして、まだ自分の書類には反映しない状態です。何も上書きしないので取り消しは不要で、pull の前の安全な下調べとして使えます。取り込んだ内容は git log origin/main などで確認できます。

```
git fetch
→ From github.com:user/repo
     aa5dcfd..1b2c3d4  main -> origin/main
```

| オプション | 意味 |
| --- | --- |
| `--all` | つながっている全部の共有先から取ってくる |
| `-p` | 相手側で消えた枝の古い情報を手元から整理する |

### 🟢 `git clone`（ギット クローン）

**見るだけ・安全**

**一言でいうと**: 共有リポジトリを丸ごとコピーして手元に置く

GitHub などにあるリポジトリを、履歴ごと自分のパソコンに複製して新しいフォルダを作ります。図書館の本を丸ごとコピーして持ち帰るイメージです。既存のファイルを上書きせず新しいフォルダを作るだけなので、いらなければそのフォルダを削除するだけで取り消せます。作業を始めるときの最初の一手です。

```
git clone https://github.com/user/repo.git
→ Cloning into 'repo'...
```

| オプション | 意味 |
| --- | --- |
| `--depth 1` | 最新分だけ浅くコピーして速く終わらせる |
| `フォルダ名` | コピー先のフォルダ名を自分で指定する |

### 🟢 `git remote`（ギット リモート）

**見るだけ・安全**

**一言でいうと**: つながっている共有リポジトリの住所を確認する

-v を付けると、送受信の相手（多くは origin という名前）とその URL が表示されます。手帳に書いた取引先の住所録を開くのと同じです。表示だけなら完全に安全で、add や remove で住所を書き換えても設定を直せば取り消せます。「今どこに送ろうとしているのか」を確かめたいときに使います。

```
git remote -v
→ origin  git@github.com:user/repo.git (fetch)
     origin  git@github.com:user/repo.git (push)
```

| オプション | 意味 |
| --- | --- |
| `-v` | 名前だけでなく URL まで表示する |
| `add 名前 URL` | 新しい送受信先を登録する |
| `remove 名前` | 登録した送受信先を外す（履歴は消えない） |

### 🟡 `git tag`（ギット タグ）

**変わるが戻せる**

**一言でいうと**: 特定のコミットに v1.0 などの目印を付ける

「ここが公開版」と分かるように、履歴の1点にラベルを貼ります。本の背に「初版」「第2版」のシールを貼るのと同じです。何も付けずに打てば一覧表示で安全、貼った目印も -d で消せるので取り消せます。ただし push --tags で外に送った後は、相手側から消すのに追加の操作が必要です。

```
git tag v1.0.0
git tag
→ v1.0.0
```

| オプション | 意味 |
| --- | --- |
| `-a 名前 -m "説明"` | 説明文付きの正式な目印を作る |
| `-d 名前` | 手元の目印を削除する |
| `-l` | 目印の一覧を表示する |

### 🟡 `git cherry-pick`（ギット チェリーピック）

**変わるが戻せる**

**一言でいうと**: 別の枝のコミットを1件だけ今の枝に持ってくる

枝ごと合流させずに、「あの修正だけ欲しい」という1件を選んで今の枝にコピーします。果物のかごから熟れた1粒だけつまむイメージで、名前の由来もそこです。中止したいときは --abort、終わった後も git revert や git reflog で戻せるので取り消せます。同じ箇所が直っているとコンフリクトになります。

```
git cherry-pick aa5dcfd
→ [main 1b2c3d4] fix: 表示のずれを直した
```

| オプション | 意味 |
| --- | --- |
| `--abort` | 持ってくるのを中止して元の状態に戻す |
| `--continue` | 衝突を直した後、続きを進める |
| `-n` | 台に載せるだけで、まだコミットしない |

### 🟢 `git blame`（ギット ブレイム）

**見るだけ・安全**

**一言でいうと**: 各行を最後に変えた人とコミットを行ごとに表示

ファイルの1行ごとに「誰が、いつ、どのコミットで書いたか」を横に並べて表示します。名前は「責める」ですが実際は、原稿の余白に誰の書き込みか名前が入っているだけの調査用です。読むだけなので何も変わらず、取り消しも不要です。「この謎の1行はなぜあるのか」を追うときに使います。

```
git blame README.md
→ aa5dcfd (akimitu 2026-07-01 1) # my-zenn
```

| オプション | 意味 |
| --- | --- |
| `-L 10,20` | 10〜20行目だけに絞って調べる |

### 🟡 `git bisect`（ギット バイセクト）

**変わるが戻せる**

**一言でいうと**: 二分探索で不具合が入ったコミットを絞り込む

「動いていた時点」と「壊れている時点」を伝えると、Git が真ん中の時点を出してきて、良い・悪いを答えるだけで犯人を挟み込んでいきます。数当てゲームで「もっと上」「もっと下」と半分ずつ範囲を狭めるのと同じ仕組みで、公式ドキュメントによれば 675 件でも約 10 回で特定できます。調査中は手元が過去の状態になりますが、git bisect reset で元の場所に戻れるので取り消せます。

```
git bisect start
git bisect bad
git bisect good v1.0
→ Bisecting: 12 revisions left to test
```

| オプション | 意味 |
| --- | --- |
| `start` | 調査を開始する |
| `good / bad` | 今の時点が正常か不具合ありかを答える |
| `reset` | 調査を終えて元の場所に戻る（必ず最後に打つ） |
| `run コマンド` | 判定を自動化して一気に犯人を探す |

### 🟡 `git worktree`（ギット ワークツリー）

**変わるが戻せる**

**一言でいうと**: 同じリポジトリを別フォルダにもう一つ展開する

1つのリポジトリから、別のフォルダに別のブランチを同時に開けます。同じ書類棚から2枚の机に別の案件を広げるイメージで、切り替えのたびに片付ける必要がなくなります。add で足し、list で確認、remove で外せるので取り消せます。remove は未保存の変更があると既定では止まってくれます。

```
git worktree add ../hotfix
git worktree list
→ /Users/me/repo      aa5dcfd [main]
     /Users/me/hotfix    1b2c3d4 [hotfix]
```

| オプション | 意味 |
| --- | --- |
| `add パス` | 指定フォルダに作業場所をもう一つ作る |
| `list` | 今ある作業場所を一覧する（安全） |
| `remove パス` | その作業場所を片付ける |

### 🟡 `git rm --cached`（ギット アールエム キャッシュド）

**変わるが戻せる**

**一言でいうと**: Git の管理から外す。ファイル自体は手元に残る

うっかり登録してしまったファイルを、履歴の追跡対象から外します。名簿から名前を消すだけで、本人（ファイル）は席に座ったままです。次のコミットで反映され、必要なら git add で戻せるので取り消せます。なお --cached を付けない git rm はファイル自体を削除するので、そちらは別物として警戒してください。

```
git rm --cached secret.txt
→ rm 'secret.txt'
```

| オプション | 意味 |
| --- | --- |
| `--cached` | 管理から外すだけ。ファイルは消さない |
| `-r` | フォルダの中身までまとめて対象にする |

### 🟢 `git reflog`（ギット リフログ）

**見るだけ・安全**

**一言でいうと**: HEAD が動いた履歴。失敗を取り消すための命綱

自分が「どこに立っていたか」の移動記録が時系列で並びます。ブラウザの履歴のようなもので、消したはずのコミットもここに残っていることが多いです。見るだけなので安全で、ここに出た番号を使えば reset や merge の失敗から復帰できます。「やってしまった」ときに最初に打つべきコマンドです。

```
git reflog
→ aa5dcfd HEAD@{0}: reset: moving to HEAD~1
     1b2c3d4 HEAD@{1}: commit: fix typo
```

### 📖 `リポジトリ`

**一言でいうと**: 変更の履歴を全部しまってある保管庫そのもの

公式用語集では「参照の集合と、そこから辿れる全オブジェクトを収めたデータベース」と定義されています。ふだんの感覚では「.git フォルダを含む、履歴つきのプロジェクトフォルダ一式」と考えて構いません。書類とその改訂履歴が全部入ったキャビネットのようなものです。手元にあるものとネット上（GitHub）にあるものの2つが対になって使われます。

```
repo/ の中に .git という隠しフォルダがあれば、それがリポジトリ
```

### 📖 `ワーキングツリー`

**一言でいうと**: いま自分が編集している作業机の上のファイル群

公式用語集では「実際にチェックアウトされたファイルの木」、つまり HEAD の内容＋まだコミットしていない自分の変更、と説明されています。要するに、エディタで開いて今まさに触っているファイルたちです。机の上に広げた書きかけの書類にあたります。ここにある未保存の変更が、reset --hard や clean で消える対象になります。

```
git status で「Changes not staged」に出てくるのがこの場所の変更
```

### 📖 `ステージング / index`（インデックス）

**一言でいうと**: コミットに入れる分を一時的に載せておく台

git add したファイルが入る中間置き場で、公式用語集では index と呼ばれます。次のコミットに含めるものだけを選んで載せる、レジのベルトコンベアや発送前の梱包台のような場所です。載せただけでは履歴に残らず、git restore --staged で降ろせます。「ステージ」「インデックス」「保存予定」は同じものを指す言い換えです。

```
git status の「Changes to be committed」に並ぶのが台に載っている分
```

### 📖 `HEAD`（ヘッド）

**一言でいうと**: いま自分がどのコミットに立っているかの現在地

公式用語集では「現在のブランチ」であり、通常はブランチ名を通して最新コミットを指しています。地図上の「現在地」ピンにあたるもので、HEAD~1 と書けば「1つ前」を意味します。switch や reset はこのピンを動かす操作です。大文字4文字で書くのが決まりです。

```
git reset --soft HEAD~1  （HEAD~1 は「1つ前のコミット」）
```

### 📖 `origin`（オリジン）

**一言でいうと**: コピー元の共有リポジトリに付く既定のあだ名

公式用語集では「既定の上流リポジトリ」と定義され、clone すると自動でこの名前が付きます。長い URL を毎回打たずに済むよう付けた短縮のあだ名で、電話帳に「本社」と登録しておくのと同じです。origin/main と書けば「共有側の main 枝の、手元が把握している状態」を指します。特別な意味の予約語ではなく、ただの慣習的な名前です。

```
git push origin main  （origin＝GitHub 上の相手先）
```

### 📖 `upstream`（アップストリーム）

**一言でいうと**: 自分の枝が既定で追いかける相手側の枝の設定

公式用語集では「その枝に対して既定で合流される相手の枝」と説明されています。これを一度決めておけば、git pull や git push を送り先なしで打てるようになります。定期購読の宛先を登録しておくイメージです。git push -u origin main の -u がこの設定を行う部分です。

```
git push -u origin main
→ branch 'main' set up to track 'origin/main'
```

### 📖 `デタッチHEAD`（デタッチト ヘッド）

**一言でいうと**: ブランチ名から外れて特定のコミットに直接立つ状態

公式用語集の説明どおり、どの枝の先端でもない任意のコミットを直接見ている状態です。しおりを挟まずに本の途中のページを開いている状態で、閉じると戻れなくなるのと同じ危うさがあります。ここでコミットするとどの枝にも属さず迷子になりやすいので、git switch -c 新しい枝名 で枝を作って引き上げるのが定石です。慌てなくても git reflog から戻せます。

```
→ You are in 'detached HEAD' state.
     HEAD detached at 9fc9555
```

### 📖 `コンフリクト`

**一言でいうと**: 同じ行を両方が別々に直したため機械が決められない状態

合流しようとした2つの変更が同じ場所を触っていて、Git がどちらを採るか判断できず止まる現象です。2人が同じ一文を別の言い回しに直した原稿を突き合わせ、どちらを残すか人が決めるしかない場面と同じです。ファイルの中に <<<<<<< と ======= と >>>>>>> の印が入るので、不要な方と印を消して保存し、add してから続けます。怖くなったら merge --abort や rebase --abort で始める前に戻せます。

```
→ CONFLICT (content): Merge conflict in app.js
     Automatic merge failed; fix conflicts and then commit
```

### 📖 `プルリクエスト`

**一言でいうと**: この変更を取り込んでくださいという依頼書

GitHub などの機能で、自分の枝の変更を本線に入れてよいかレビューしてもらう依頼です。Git 本体の機能ではなくサービス側の仕組みで、略して PR と書かれます。稟議書を回して押印をもらう手続きに近く、コメントで議論しながら直せます。作った後も閉じられるので、作成自体は取り消せます。

```
gh pr create の実行後に出る https://github.com/user/repo/pull/12
```

### 📖 `フォーク`

**一言でいうと**: 他人のリポジトリを自分の場所へ丸ごと複製したもの

GitHub 上で、書き込み権限のない他人のリポジトリを自分の持ち物としてコピーする機能です。Git 本体の用語ではなくサービス側の概念です。図書館の本を自分用にコピーして自由に書き込めるようにするイメージで、直した内容はプルリクエストで元の作者に提案します。clone（手元へコピー）とは別の話なので混同しないよう注意してください。

```
gh repo fork user/repo
```

### 📖 `.gitignore`（ドットギットイグノア）

**一言でいうと**: Git に見せなくていいファイルを書いておく一覧表

公式ドキュメントによれば「意図的に追跡しないファイル」を指定する設定ファイルです。パスワードを含む .env や自動生成物などを毎回無視させるための除外リストで、掃除の際に「この棚は触らないで」と貼る札に似ています。重要な注意として、すでに登録済みのファイルには効きません。その場合は git rm --cached で管理から外してから書き足す必要があります。

```
*.log
.env
node_modules/
```

### 📖 `コミット`

**一言でいうと**: ある時点の状態に名前を付けて保存した記録1件

変更のまとまりに説明文と作成者・日時を添えて履歴に固定した、1件のスナップショットです。原稿を封筒に入れて表書きし、日付印を押して綴じたものにあたります。aa5dcfd のような英数字（ハッシュ）が名前になり、これを指定して見たり戻したりします。動詞としては「保存する操作」も指します。

```
aa5dcfd chore: initialize zenn-cli project
```

### 📖 `ブランチ`

**一言でいうと**: 本線を汚さず作業するために伸ばした履歴の枝

ある時点から分かれて、独立して進められる作業の系列です。清書済みの原稿はそのままに、別のコピーで書き直しを試すのと同じで、失敗しても本線に影響しません。main（本線）から feature/ログイン画面 のような枝を作り、できたら合流させます。中身はコミットを指す小さな付箋なので、作るのも消すのも軽い操作です。

```
git branch
→ * main
     feature/login
```

### 🟡 `gh auth login`（ジーエイチ オース ログイン）

**変わるが戻せる**

**一言でいうと**: GitHub に本人確認してコマンドから操作できるようにする

GitHub CLI（gh コマンド）に「自分はこのアカウントです」と登録し、以後 PR 作成などができるようにします。社内システムに初回ログインして端末を認証するのと同じ手続きです。ブラウザが開いて確認コードを入れる流れが一般的で、gh auth logout で解除できるので取り消せます。認証情報が端末に保存されるので、共用のパソコンでは注意してください。

```
gh auth login
→ ? What account do you want to log into? GitHub.com
```

| オプション | 意味 |
| --- | --- |
| `--web` | ブラウザを開いて認証する |

### 🟡 `gh pr create`（ジーエイチ ピーアール クリエイト）

**変わるが戻せる**

**一言でいうと**: いまの枝からレビュー依頼を GitHub 上に作る

公式マニュアルによれば、現在の枝からプルリクエストを作り、成功すると URL を表示します。稟議書を作って回覧に出すのと同じで、出した後もコメントで直せます。タイトルと本文を渡さないと質問形式で聞かれ、まだ送信していない枝なら送信も提案されます。閉じれば取り消せますが、内容が外部に公開されるので実行前に一言確認してください。

```
gh pr create --title "ログイン修正" --body "表示崩れを直しました"
→ https://github.com/user/repo/pull/12
```

| オプション | 意味 |
| --- | --- |
| `--title` | 依頼のタイトルを指定する |
| `--body` | 説明本文を指定する |
| `--draft` | 下書き状態で作る（まだレビュー依頼にしない） |
| `--base 枝名` | どの枝へ取り込む依頼かを指定する |
| `--fill` | コミットの内容からタイトルと本文を自動で埋める |
| `--web` | コマンドで作らずブラウザを開く |

### 🟢 `gh pr view`（ジーエイチ ピーアール ビュー）

**見るだけ・安全**

**一言でいうと**: プルリクエストの内容や状態を見るだけのコマンド

タイトル、説明、レビュー状況などを画面に表示します。回覧中の稟議書を手元で開いて眺めるだけの動作です。何も変えないので取り消しは不要で、番号を省くと今の枝に紐づく PR を見せます。--web を付けるとブラウザで開きます。

```
gh pr view 12
→ ログイン修正 #12  Open • akimitu wants to merge 2 commits
```

| オプション | 意味 |
| --- | --- |
| `--web` | ブラウザで開いて見る |
| `--comments` | 付いたコメントも一緒に表示する |

### 🟡 `gh pr checkout`（ジーエイチ ピーアール チェックアウト）

**変わるが戻せる**

**一言でいうと**: 他人のプルリクエストを手元に取り出して確認する

指定した PR の枝を自分のパソコンに持ってきて切り替え、実際に動かして確かめられます。回覧された書類を手元にコピーして中身を精査するイメージです。元の枝に git switch で戻れるので取り消せます。ただし手元に未保存の編集があると切り替えに失敗することがあるので、先に commit か stash を。

```
gh pr checkout 12
→ Switched to branch 'feature/login'
```

### 🔴 `gh pr merge`（ジーエイチ ピーアール マージ）

**止めて確認**

**一言でいうと**: プルリクエストを本体に取り込む。取り込み＝反映

レビューが終わった依頼を本線に合流させ、設定によってはそのまま自動デプロイ（本番反映）まで走ります。稟議に最終決裁の印を押す操作で、押した後の巻き戻しは関係者全員に影響します。取り消しは技術的には可能ですが、外に出た影響は消えません。実行前に必ず人に確認してください。

```
gh pr merge 12 --squash
→ Merged pull request #12
```

| オプション | 意味 |
| --- | --- |
| `--squash` | コミットを1件にまとめて取り込む |
| `--merge` | 合流の記録を残す形で取り込む |
| `--delete-branch` | 取り込み後に元の枝を削除する |

### 🟢 `gh repo clone`（ジーエイチ レポ クローン）

**見るだけ・安全**

**一言でいうと**: GitHub のリポジトリを手元にコピーして持ってくる

git clone と同じことを、URL を打たずに「user/repo」の指定だけで済ませられます。認証情報を使ってくれるので、非公開のリポジトリでもそのまま取得できます。図書館の本を貸出カードだけで借りるイメージです。新しいフォルダを作るだけなので、消せば取り消せます。

```
gh repo clone akimitu/my-zenn
→ Cloning into 'my-zenn'...
```

### 🟢 `gh run list`（ジーエイチ ラン リスト）

**見るだけ・安全**

**一言でいうと**: GitHub 上の自動処理の実行結果を一覧で見る

GitHub Actions（送信のたびに自動で走るテストや公開処理）の実行結果が新しい順に並びます。工場のラインの稼働ログを眺めるイメージで、成功か失敗かが記号で分かります。見るだけなので安全で、失敗を見つけたら gh run view で詳細を確認できます。「push したのに反映されない」ときの最初の確認先です。

```
gh run list
→ ✓ build  main  push  2m ago
     X test   main  push  5m ago
```

| オプション | 意味 |
| --- | --- |
| `--limit 5` | 表示件数を絞る |

### 🟢 `gh issue list`（ジーエイチ イシュー リスト）

**見るだけ・安全**

**一言でいうと**: GitHub の課題・要望チケットを一覧で見る

バグ報告や「こうしたい」という要望が、番号と題名の一覧で表示されます。付箋を貼った ToDo ボードを眺めるのと同じです。見るだけなので何も変わらず、取り消しも不要です。番号を gh issue view に渡せば1件の詳細が読めます。

```
gh issue list
→ #7  ログインできない  bug
     #9  文言を直したい   docs
```

| オプション | 意味 |
| --- | --- |
| `--state open` | 未対応のものだけに絞る |
| `--assignee @me` | 自分が担当のものだけに絞る |
