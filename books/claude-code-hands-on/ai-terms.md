### 📖 `prompt`（プロンプト）

**一言でいうと**: AIに出す指示文そのもの。あなたが打ち込む言葉が全部これ

AIに「こうしてほしい」と伝える文章のことです。料理店で店員さんに伝える注文にあたります。「塩少なめで」と細かく言えばその通りに近づくのと同じで、プロンプトが具体的なほど返ってくる結果も狙いに近づきます。逆にあいまいだと、AIは勝手に想像で埋めてしまいます。

```
ログイン画面のボタンの色を青に変えて、変更したファイルを教えて
```

### 📖 `system prompt`（システムプロンプト）

**一言でいうと**: AIの性格や役割をあらかじめ決めておく、裏側の指示書

あなたが打つプロンプトとは別に、会話の一番最初に読み込まれる「基本ルール」の文章です。アルバイト初日に渡される店のマニュアルにあたります。Claude Code のシステムプロンプトはふるまい方・道具の使い方・返答の書き方を決めていて、公式ドキュメントにも「あなたが目にすることはない」と書かれています。

```
画面には表示されない（/context を実行すると「System prompt」として容量だけ見える）
```

### 📖 `token`（トークン）

**一言でいうと**: AIが文章を数える単位。文字より少し大きい「かたまり」

AIは文章を単語や文字の切れはしに分解してから読みます。その1つ1つがトークンです。英語ならだいたい3.5文字で1トークンほど、と Anthropic の用語集は説明しています。お米を「粒」ではなく「合」で量るように、AIの世界では文字数ではなくトークン数で「どれだけ読んだか・書いたか」を数えます。料金や上限もこの単位で決まります。

```
Total: 45.2k tokens (23%)
```

### 📖 `context`（コンテキスト）

**一言でいうと**: AIが今この瞬間に覚えている情報のかたまり

これまでの会話、開いたファイルの中身、コマンドの実行結果など、AIが「今わかっている」情報の全体です。机の上に広げた資料にあたります。机に載っていないことはAIには見えないので、大事な資料は載せる（ファイルを読ませる）必要があります。

```
/context と入力すると、今なにが何トークン分載っているかが一覧で出る
```

### 📖 `context window`（コンテキストウィンドウ）

**一言でいうと**: AIが一度に覚えられる量の上限。作業机の広さ

AIの「作業机の広さ」です。Anthropic の用語集では、学習した膨大な知識とは別の、その場限りの作業記憶（ワーキングメモリ）だと説明されています。机が広ければ多くの資料を同時に見られますが、限界はあります。いっぱいになると古い資料から片付けられていくので、長い作業では話が抜け落ちることがあります。

```
Context left until auto-compact: 12%
```

### 📖 `compaction`（コンパクション）

**一言でいうと**: 会話が長くなりすぎた時に、AIが自分で要約して席を空ける動作

コンテキストウィンドウが埋まりそうになると、Claude Code が会話を自動で要約して圧縮します。散らかった机の資料を「要点メモ1枚」にまとめ直す作業にあたります。公式ドキュメントによると、まず古いコマンド結果が消され、次に会話が要約されます。プロジェクト直下の CLAUDE.md は圧縮後も読み直されますが、会話の中だけで伝えた指示は消えることがあります。

```
/compact focus on the API changes （「API の変更点を残して要約して」の意味）
```

| オプション | 意味 |
| --- | --- |
| `/compact` | 今すぐ手動で要約させる |
| `/compact <残したい話題>` | 何を優先して残すか指定する |

### 📖 `session`（セッション）

**一言でいうと**: ひとつづきの会話のかたまり。作業ごとの「部屋」

今いるフォルダに紐づいた、独立した会話のかたまりです。会議室を1つ借りているイメージで、部屋ごとに机（コンテキストウィンドウ）が別々にあります。/clear で新しい部屋に移りますが、前の部屋の記録は残っていて /resume で戻れます。記録は ~/.claude/projects/ の下に保存されます。

```
claude -c （直前のセッションを再開する）
```

| オプション | 意味 |
| --- | --- |
| `-c` | 直前のセッションを再開する |
| `--fork-session` | 履歴を引き継いだまま別セッションとして枝分かれさせる |
| `/clear` | 新しいセッションを始める |
| `/resume` | 保存済みのセッションを選んで戻る |

### 📖 `turn`（ターン）

**一言でいうと**: あなたが1回話しかけてAIが返し終わるまでの1往復

あなたがメッセージを送った時に始まり、AIが返答を終えた時に終わる1回分です。途中でAIが何十回ファイルを読んだり動かしたりしても、それはまだ1ターンの中です。将棋の「一手」と同じ数え方で、1つのセッションは何十ターンもの積み重ねでできています。

```
--max-turns 5 （CI などで往復回数に上限をつける指定）
```

| オプション | 意味 |
| --- | --- |
| `--max-turns` | 何往復までで打ち切るかを決める |

### 📖 `thread`（スレッド）

**一言でいうと**: 1つの話題でつながった会話の連なり

1つの話題について続いているやりとりの筋道です。LINE の「返信」でつながった一連のメッセージにあたります。Claude Code を Slack から使う場合、スレッドの中で @Claude を呼ぶと、そのスレッド全部のメッセージを読んで状況を把握してくれます。

```
Slack のバグ報告スレッドの中で「@Claude これ直せる?」と返信する
```

### 📖 `checkpoint`（チェックポイント）

**一言でいうと**: 作業前の状態に戻せる、自動セーブポイント

あなたが指示を送るたびに作られる「復元ポイント」です。Claude Code はファイルを書き換える前に状態を保存しておくので、あとから元に戻せます。ゲームのセーブデータと同じ発想です。Esc を2回押すか /rewind で、コードだけ・会話だけ・両方、のどれを戻すか選べます。ただし git とは別のしくみで、Bash コマンド経由の変更は追跡されません。

```
Esc Esc を押す、または /rewind と入力する
```

| オプション | 意味 |
| --- | --- |
| `/rewind` | 戻す対象（コード・会話・両方）を選んで復元する |

### 📖 `model`（モデル）

**一言でいうと**: AIの頭脳の種類。賢さと速さと値段が違う

実際に考えている中身のAIそのものです。Opus・Sonnet・Haiku のように種類があり、車のグレードのように「賢いが遅くて高い」「軽快で安い」といった違いがあります。難しい設計の相談は上位モデル、単純な書き換えは軽いモデル、と使い分けます。/model で切り替えられます。

```
/model と入力すると、使えるモデルの一覧から選べる
```

| オプション | 意味 |
| --- | --- |
| `/model` | 使うモデルを切り替える |

### 📖 `LLM`（エルエルエム）

**一言でいうと**: 大規模言語モデル。文章の続きを予想する巨大なAI

Large Language Model の略で「大規模言語モデル」です。膨大な文章を読んで「次にどんな言葉が来るか」を予想する訓練を積んだAIで、Claude もこの仲間です。次の言葉を当て続けるという意味では、スマホの予測変換をとてつもなく巨大にしたものと言えます。

### 📖 `temperature`（テンパラチャー）

**一言でいうと**: 答えのばらつき具合の設定。高いほど自由、低いほど堅実

AIの言葉選びをどれだけ冒険させるかの数値です。高いと表現が多様で創作向き、低いと無難で毎回似た答えになります。料理人に「いつも通りで」と頼むか「好きにアレンジして」と頼むかの違いです。なお Anthropic は、0 にしても完全に同じ結果になるとは限らないと明記しています。

```
temperature: 0.7
```

### 📖 `extended thinking`（エクステンデッドシンキング）

**一言でいうと**: AIが答える前に考えた内容を、見える形で書き出すこと

返答する前の思考過程を段階的に表に出すしくみです。ターミナルでは灰色の斜体で表示されます。試験で答えだけ書くのではなく、計算の途中式を書いてから答えを出すようなものです。込み入った判断では精度が上がりますが、その分トークンと時間を使います。

```
画面に灰色の斜体で「Thinking…」と考えている内容が流れる
```

| オプション | 意味 |
| --- | --- |
| `MAX_THINKING_TOKENS` | 考える量に上限を設ける環境変数（思考量が固定式のモデル向け） |

### 📖 `effort level`（エフォートレベル）

**一言でいうと**: AIにどれくらい念入りに考えさせるかのつまみ

1回のやりとりでどれだけ深く考えるかを決める設定です。高くすると思考のトークンを多く使って深く考え、低くすると速くて安くなります。エアコンの「強・弱」つまみと同じ感覚です。Fable 5、Opus 4.6 以降、Sonnet 4.6 以降で使えます。

```
/effort high
```

| オプション | 意味 |
| --- | --- |
| `/effort` | 考える深さを切り替える |
| `--effort` | 起動時に指定する |

### 📖 `agent`（エージェント）

**一言でいうと**: 自分で手を動かして仕事を進めてくれるAI

文章を返すだけでなく、ファイルを読み、書き換え、コマンドを実行して作業を完了させるAIです。レシピを教えてくれる人ではなく、台所に立って実際に作ってくれる人にあたります。だからこそ「何を触っていいか」の許可が重要になります。

### 📖 `agentic`（エージェンティック）

**一言でいうと**: AIが自分で判断して動く方式であること

「エージェント的な」という形容詞です。公式には、AIがファイルを読み・コマンドを走らせ・自律的に変更を加える進め方を指し、あなたはそれを見守ったり方向転換させたり席を外したりできると説明されています。助言だけのチャットとの違いは、道具（ツール）を持って実際に動けるかどうかです。

```
agentic coding tool（自分で動くコーディング道具）という紹介文で使われる
```

### 📖 `agentic loop`（エージェンティックループ）

**一言でいうと**: 情報を集める→動く→確かめる、を繰り返すAIの作業サイクル

Claude が毎回のタスクで回している循環のことです。状況を集め、手を動かし、結果を確かめ、終わるまで繰り返します。料理で「味見して、足して、また味見する」を繰り返すのと同じです。あなたはこの輪の途中でいつでも口を挟んで方向を変えられます。

### 📖 `agentic harness`（エージェンティックハーネス）

**一言でいうと**: AIに手足と道具を与える「外側の入れ物」

言語モデルを実際に働けるエージェントに変えている、道具・記憶管理・実行環境のまとまりです。公式は「Claude Code がハーネスで、Claude はその中のモデル」と説明しています。運転手（モデル）に対する自動車（ハーネス）の関係です。ファイル操作、コマンド実行、許可の確認などを担います。

### 📖 `subagent`（サブエージェント）

**一言でいうと**: 本体とは別の机を持つ、下請け専門のAI

独自のコンテキストウィンドウ、独自の役割指示、限定した道具と権限を持つ専用のAIです。任された調べものを済ませて、要約だけを本体の会話に戻します。膨大な資料を別室で読んでもらい、A4一枚の報告書だけ受け取るイメージです。本体の机を散らかさずに済むのが利点で、Explore・Plan・general-purpose が最初から用意されています。

```
「サブエージェントを3つ並列で走らせて調べて」と頼む
```

### 📖 `agent teams`（エージェントチーム）

**一言でいうと**: 複数のAIがチームを組み、リーダー役がまとめる進め方

独立した複数の Claude Code セッションが、リーダー役のもとで共有のタスク一覧を見ながら働くしくみです。サブエージェントと違い、1人1人が自分の机を持ち、あなたが誰にでも直接話しかけられます。実験的な機能で、CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1 を設定しないと使えません。

| オプション | 意味 |
| --- | --- |
| `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` | この実験機能を有効にする環境変数 |

### 📖 `orchestration`（オーケストレーション）

**一言でいうと**: 複数のAIに役割を振り、順番と受け渡しを取りしきること

誰にどの仕事をいつやらせ、結果をどうまとめるかを指揮することです。まさに指揮者がオーケストラをまとめるのと同じで、語源もそこです。Claude Code では、Claude 自身が指揮するやり方（サブエージェント）と、台本の形に書き出して指揮を固定するやり方（ワークフロー）があります。

### 📖 `dynamic workflow`（ダイナミックワークフロー）

**一言でいうと**: AIへの指示手順を台本として書き出し、何度も使い回すしくみ

たくさんのサブエージェントを動かす段取りを、Claude が JavaScript の台本として書き出して裏で実行するしくみです。毎回口頭で段取りを説明する代わりに、印刷した進行表を渡すようなものです。1回の実行で最大16体が同時に動き、合計1000体までという上限があります。トークン消費は大きめなので、まず小さい範囲で試すのが公式の勧めです。

```
/deep-research Node.js のバージョン間で何が変わったか
```

| オプション | 意味 |
| --- | --- |
| `/workflows` | 動いている・終わった実行の一覧と進み具合を見る |
| `ultracode` | プロンプトに含めると、その仕事を台本方式で進めさせる合図になる |

### 📖 `tool`（ツール）

**一言でいうと**: AIが使える道具。ファイルを読む・コマンドを打つなどの手段

ファイルを読む、コードを直す、コマンドを走らせる、ウェブを検索する、といったAIが取れる行動のことです。公式は「道具がなければ Claude は文章を返すことしかできない」と説明しています。大工に金づちとのこぎりを渡すのと同じで、道具の分だけできることが増えます。

```
画面に「Read(src/app.ts)」「Bash(npm test)」のように、使った道具と対象が表示される
```

### 📖 `tool use / function calling`（ツールユース／ファンクションコーリング）

**一言でいうと**: AIが「この道具を使いたい」と申し出て、実際に動かすしくみ

AIが状況を見て「今はこの機能を呼ぶべきだ」と判断し、呼び出しの内容を組み立てて返すしくみです。呼び名は2つありますが、ほぼ同じことを指します。Anthropic の説明では、あなたの側で実行する道具（クライアントツール）と、Anthropic 側で実行される道具（サーバーツール）があります。レストランで店員が厨房に注文票を回すのと同じ流れです。

### 📖 `MCP (Model Context Protocol)`（エムシーピー）

**一言でいうと**: AIと外部サービスをつなぐ共通の差し込み口の規格

AIを社外のデータやサービスにつなぐための、公開された共通ルールです。Anthropic 自身が「AIアプリの USB-C ポートのようなもの」と説明しています。差し込み口の形が統一されているから、Slack でも Jira でもデータベースでも同じやり方でつなげます。Claude Code では /mcp か .mcp.json で接続します。

```
/mcp と入力すると、つながっているサービスの一覧が出る
```

| オプション | 意味 |
| --- | --- |
| `/mcp` | 接続中のサービスを確認する |
| `claude mcp add` | 新しい接続先を追加する |

### 📖 `MCP server`（エムシーピーサーバー）

**一言でいうと**: AIに新しい道具を渡してくれる小さなプログラム

MCP の決まりに従って、Claude に道具や情報を提供するプログラムのことです。「サーバー」という名前ですが、自分のパソコンの中で動く小さなものも含みます。工具箱を1つ持ってきてくれる助手にあたります。1つ足すたびに Claude ができることが増えます。

```
.mcp.json に接続設定を書く、または claude mcp add で追加する
```

### 📖 `MCP Tool Search`（エムシーピーツールサーチ）

**一言でいうと**: 道具の説明書を、必要になるまで読み込まないで机を節約するしくみ

接続した道具の詳しい仕様書をあらかじめ全部読むのではなく、名前だけ覚えておいて使う時に取り寄せるしくみです。分厚い取扱説明書を全部机に積むかわりに、背表紙だけ並べて必要な1冊だけ開く感覚です。これで使っていない接続がコンテキストウィンドウを食いつぶすのを防げます。

| オプション | 意味 |
| --- | --- |
| `ENABLE_TOOL_SEARCH=false` | 仕様書を最初から全部読み込む設定に戻す |

### 📖 `skill`（スキル）

**一言でいうと**: 作業手順をまとめた説明書。AIが必要な時に読んで実行する

SKILL.md というファイルに書いた手順や知識のかたまりです。Claude は関係ありそうな時に自分で読み込み、/名前 で直接呼ぶこともできます。よく作る料理のレシピカードを引き出しにしまっておくのと同じで、毎回口で説明しなくて済みます。公式では、昔の「カスタムコマンド」の後継として推奨されています。

```
/code-review と入力すると、コードレビュー用の手順書が読み込まれて実行される
```

### 📖 `hook`（フック）

**一言でいうと**: 決まった場面で必ず自動実行される、仕込みの処理

「ファイルを直した直後」「セッション開始時」など、決まったタイミングで自動的に走る処理です。玄関のドアに付けた自動点灯センサーと同じで、AIの気分に関係なく必ず作動します。公式が「決定的（deterministic）」と書いているのはこの点で、たとえば編集のたびに自動整形をかける、といった使い方をします。

```
「ファイルを編集したら毎回 prettier を走らせる」設定を .claude/settings.json に書く
```

### 📖 `command / slash command`（コマンド／スラッシュコマンド）

**一言でいうと**: 先頭に / を付けて呼び出す、決まった機能のショートカット

入力欄に /名前 と打って呼び出す機能です。/clear や /model のように最初から入るものと、自分で作るものがあります。テレビのリモコンのボタンにあたり、長い説明を打たずに一発で呼べます。なお公式の用語集では「スラッシュ」という言い方は製品表記から外され、単に「コマンド」と呼ばれるようになりました。

```
/ を打つと、使えるコマンドの候補が一覧で出てくる
```

### 📖 `CLAUDE.md`（クロードエムディー）

**一言でいうと**: 毎回必ず読ませる、プロジェクトのルールを書いた紙

あなたが書いておく指示書で、セッションが始まるたびに自動で読み込まれます。「この書き方で統一」「このライブラリを使う」といった決まり事を置く場所です。新人に毎回口で説明せず、机に貼っておく作業ルールと同じです。プロジェクト直下のものは要約（コンパクション）後も残り、ディスクから読み直されます。

```
プロジェクトの一番上の階層に CLAUDE.md というファイルを置く
```

### 📖 `auto memory`（オートメモリー）

**一言でいうと**: AIが自分のために書き残していく気づきメモ

あなたの指摘や好みをもとに、Claude が自分で書きためていくメモです。CLAUDE.md が「あなたが書く紙」なら、こちらは「AIが書く紙」です。新人が自分の手帳にコツを書き溜めていくのと同じで、次の日に同じ失敗をしにくくなります。git リポジトリごとに ~/.claude/projects/ の下へ保存され、毎回その目次の先頭部分が読み込まれます。

```
MEMORY.md
```

### 📖 `plan mode`（プランモード）

**一言でいうと**: AIが調べて計画を出すだけで、ファイルは一切触らないモード

Claude が読む・探す・調査コマンドを走らせるところまではやるものの、あなたのファイルは書き換えず、先に計画を提示して承認を待つモードです。リフォーム業者が見積もりと図面を先に見せてくれるのと同じで、いきなり壁を壊されません。よくわからない作業を頼む時ほど、まずここから始めると安全です。

```
/plan と入力する、または Shift+Tab を押して切り替える
```

| オプション | 意味 |
| --- | --- |
| `/plan` | プランモードに入る |
| `Shift+Tab` | モードを順番に切り替える |

### 📖 `permission mode`（パーミッションモード）

**一言でいうと**: どこまで勝手にやらせるかの基本設定。全体の緩さのつまみ

「毎回聞いてくる」から「ほぼ聞かずに進む」までの基本姿勢を決める設定です。default（画面表示は Manual）、acceptEdits、plan、auto、dontAsk、bypassPermissions があります。新人に「一つずつ報告して」と言うか「任せる」と言うかの違いです。CLI では Shift+Tab で切り替えます。

```
Shift+Tab を押すと、画面下の表示が Manual → accept edits → plan… と変わる
```

| オプション | 意味 |
| --- | --- |
| `Shift+Tab` | モードを切り替える |

### 📖 `auto mode`（オートモード）

**一言でいうと**: 別のAIが横で安全確認して、確認画面をほぼ出さなくするモード

裏で別の判定用AI（クラシファイア）が一つ一つの行動を見張り、問題なければ確認を出さずに進めるモードです。危ない範囲の拡大、信頼できない接続先、プロンプトインジェクションを止めます。工場のラインで別の検査員が横に立っているイメージです。この判定役は道具の実行結果を一切見ないので、外部から埋め込まれた指示に釣られない作りになっています。

### 📖 `permission rule / allowlist`（パーミッションルール／アローリスト）

**一言でいうと**: どの操作を許すか禁じるかを1つずつ書いた、通行許可の名簿

道具の名前と対象のパターンで、許可（allow）・確認する（ask）・禁止（deny）を細かく決める設定です。allowlist は「これは通してよい」側の名簿にあたり、マンションの入館許可リストと同じ発想です。公式によると、判定は deny → ask → allow の順に見て、最初に当てはまったものが勝ちます。

```
/permissions と入力すると、今の許可・確認・禁止の一覧を編集できる
```

| オプション | 意味 |
| --- | --- |
| `/permissions` | 許可の一覧を確認・編集する |

### 📖 `sandbox`（サンドボックス）

**一言でいうと**: AIの作業範囲をOSレベルで囲い込む、砂場の柵

コマンドが触れるファイルとつなげる接続先を、あらかじめ決めた境界の中に閉じ込めるしくみです。子どもを砂場の柵の中で自由に遊ばせるのと同じで、外に出られないから中では確認なしで動かせます。既定では作業フォルダと一時フォルダにしか書き込めず、新しい接続先が必要になった時だけ確認が出ます。macOS・Linux・WSL2 で使え、Windows 直では動きません。

```
/sandbox と入力すると、設定画面（Mode / Overrides / Config）が開く
```

| オプション | 意味 |
| --- | --- |
| `/sandbox` | サンドボックスの設定画面を開く |

### 📖 `worktree isolation`（ワークツリーアイソレーション）

**一言でいうと**: 作業用のコピーを別フォルダに作り、他とぶつからないようにすること

git の worktree という機能を使い、別のフォルダ・別の枝（ブランチ）で作業させるしくみです。同じ書類を2人で同時に直して上書き合戦になるのを避けるため、それぞれに複写を渡すのと同じです。Claude Code では -w を付けると .claude/worktrees/ の下に作られ、複数のAIを並行で動かしても互いのファイルを壊しません。

```
claude -w
```

| オプション | 意味 |
| --- | --- |
| `-w` | 別のワークツリーに隔離して起動する |

### 📖 `non-interactive mode (旧 headless)`（ノンインタラクティブモード（旧ヘッドレス））

**一言でいうと**: 指示を1回だけ実行して終わる、対話画面なしの動かし方

入力欄を出さずに、渡した指示を1回実行してそのまま終了する使い方です。自動販売機のように、押したら出て終わり、という動きです。CI や自動処理、他のコマンドとのつなぎ込みに使います。公式用語集では、以前 headless mode と呼ばれていたものが現在の呼び名に変わったと明記されています。

```
tail -200 app.log | claude -p "異常があれば教えて"
```

| オプション | 意味 |
| --- | --- |
| `-p / --print` | 1回実行して終了する |
| `--bare` | フックやスキルなどの自動読み込みを飛ばし、環境差をなくす |

### 📖 `artifact`（アーティファクト）

**一言でいうと**: 結果を見やすいウェブページとして出してくれる成果物

ターミナルの文字を読む代わりに、claude.ai 上の非公開URLに見やすいページとして結果を出す機能です。作り直すと同じURLが更新されます。報告書を口頭ではなく1枚の資料にして渡すのと同じです。共有できる範囲は契約プランによって変わります。

```
「集計結果をアーティファクトにして」と頼むと、開けるURLが返ってくる
```

### 📖 `prompt injection`（プロンプトインジェクション）

**一言でいうと**: 外部の文章にAI向けの悪い命令を仕込む攻撃

ファイルやウェブページ、道具の実行結果の中に、AIを乗っ取るための命令をまぎれ込ませる攻撃です。読んだAIが、あなたが頼んでいない行動を取るよう誘導されます。届いた郵便物に「金庫の鍵を送れ」と書いた偽の社内メモを混ぜる手口と同じです。Claude Code 側は許可のしくみ、コマンド混入の検出、信頼の確認で防ぎます。

### 📖 `guardrail`（ガードレール）

**一言でいうと**: AIが踏み外さないよう外側から掛けておく安全の枠

AIの出力や入力を別のしくみで見張り、危ない内容をはじく安全策の総称です。Anthropic の記事では、1つのAIが質問に答え、別のAIがその内容を審査する形が挙げられており、同じAIに両方やらせるより結果が良いとされています。道路のガードレールと同じで、走るのは自由だが崖には落ちない、という発想です。

### 📖 `hallucination`（ハルシネーション）

**一言でいうと**: AIがもっともらしい嘘を、自信たっぷりに言ってしまうこと

実際には存在しない事実や機能を、事実のように答えてしまう現象です。日本語では「幻覚」と訳されます。うろ覚えの話を自信満々に語る人と同じで、口調が堂々としているぶん見抜きにくいのが厄介です。Anthropic は目指す姿として「正直（honest）なAIは幻覚を作らず、わからない時は限界を認める」と掲げています。

```
存在しないコマンドやオプションを、あるかのように答えてしまう
```

### 📖 `RAG`（ラグ）

**一言でいうと**: 答える前に関連資料を探して読ませ、根拠付きで答えさせる方式

Retrieval Augmented Generation の略で「検索して補強した生成」です。質問が来たらまず外部の資料庫から関係する文書を取り出し、それを質問と一緒にAIに渡してから答えさせます。記憶だけで答えるのではなく、図書館で該当ページを引いてから答える人にあたります。学習時点にない最新情報や社内独自の知識を扱うのに向きますが、資料庫の質がそのまま答えの質になります。

### 📖 `embedding`（エンベディング）

**一言でいうと**: 文章の意味を数字の並びに変換したもの

文章や単語の「意味」を数百個の数字の列に置き換えたものです。意味が近い文章は数字の並びも近くなるので、言葉が違っても内容が似ているものを見つけられます。色を「赤」「朱色」という名前ではなく数値で表せば近さが計算できる、というのと同じ理屈です。Anthropic は自社では作らず、Voyage AI を推奨しています。

### 📖 `vector`（ベクトル）

**一言でいうと**: 意味を表す数字の並びそのもの。近さで似た文書を探せる

エンベディングで作られた数字の列そのものをこう呼びます。それを大量に貯めて「似ているもの」を高速に探す保管庫がベクトルデータベース（vector database）で、RAG の土台になります。地図上の座標のようなもので、座標が近ければ内容も近い、という探し方ができます。

```
vector database（ベクトルデータベース）
```

### 📖 `fine-tuning`（ファインチューニング）

**一言でいうと**: できあがったAIに追加で学習させ、性質を寄せること

すでに訓練済みのAIに追加のデータで学習させ、その分野の言い回しや傾向を身につけさせる作業です。ベテランに自社のやり方を追加で覚えてもらう研修にあたります。Claude はすでに助手としてファインチューニングされた状態で、Anthropic の説明では Claude API では現在この機能は提供されていません。

### 📖 `few-shot / multishot`（フューショット／マルチショット）

**一言でいうと**: お手本を数個見せて、やり方を真似させる指示のしかた

「こう入れたらこう返してほしい」という例をいくつか添えて頼む方法です。長々と説明するより、見本を並べたほうが早く伝わります。新人に完成品のサンプルを3つ見せて「こういう感じで」と言うのと同じです。Anthropic のドキュメントでは multishot prompting という名前で扱われています。

```
入力: 田中太郎 → 出力: TANAKA Taro / 入力: 山田花子 → 出力: ...（と例を並べて頼む）
```

### 📖 `chain of thought`（チェーンオブソート）

**一言でいうと**: 順を追って考えさせる指示のしかた。思考の連鎖

答えを即答させず、段階を踏んで考えさせるやり方です。日本語では「思考の連鎖」と訳されます。暗算で答えだけ言うのではなく、筆算を書いてから答えを出させると間違いが減るのと同じです。略して CoT とも書かれ、AIの機能として組み込まれた extended thinking と同じ考え方に基づいています。

```
手順を1つずつ書き出してから、最後に結論を書いてください
```

### 📖 `eval`（イーバル）

**一言でいうと**: AIの出来を採点するテスト。当てずっぽうの改善を防ぐ

evaluation の略で「評価」です。Anthropic の説明では、AIに入力を与え、その出力に採点ルールを当てて成否を測るテストのことです。味見だけで調味料を足すのではなく、決めた基準で毎回採点して比べる、という進め方です。これがないと、プロンプトを直して良くなったのか悪くなったのか、雰囲気でしか判断できません。

### 📖 `latency`（レイテンシ）

**一言でいうと**: 頼んでから返ってくるまでの待ち時間

指示を送ってから結果が返るまでの遅れのことです。日本語では「遅延」です。注文してから料理が出てくるまでの時間にあたり、短いほど会話が快適になります。モデルの大きさ、通信状況、指示の複雑さで変わります。最初の1文字が出るまでの時間だけを見る TTFT（Time to First Token）という指標もあります。

### 📖 `streaming`（ストリーミング）

**一言でいうと**: 答えを書き終わるのを待たず、少しずつ流して表示すること

全部完成してから見せるのではなく、できた部分から順に画面へ流す方式です。文字がタタタと流れていくあの表示がこれです。全皿そろうまで待たされるコースではなく、できた皿から順に出てくる食事にあたります。待ち時間の体感が短くなるので、対話型では標準的に使われます。

```
画面に文字が少しずつ現れていく（一気にどんと出ない）
```

### 📖 `rate limit`（レートリミット）

**一言でいうと**: 決まった時間内に使える回数・量の上限

一定の時間あたりに送れる要求の上限です。Anthropic の説明では、たとえば毎分60回の上限が「1秒あたり1回」として運用されることがあります。高速道路の入口で車を間隔を空けて流す信号（ランプメーター）と同じ発想で、全体が詰まらないよう手前で絞っています。ぶつかると、上限が回復する時刻まで待つことになります。

```
Rate limit reached. Try again at 15:30.
```

### 📖 `usage limit`（ユーセージリミット）

**一言でいうと**: プランごとに決まった、一定期間で使い切れる持ち分

契約プランに応じて「この期間内にこれだけ使える」と決まっている持ち分です。携帯電話の月間データ容量と同じで、使い切ると回復まで待ちます。Claude Code の上限は claude.ai やデスクトップアプリと共通の枠から引かれ、5時間ごとの枠と週ごとの枠があります。モデルを切り替えても枠は共有なので、変えれば復活する、ということはありません。

```
/status と入力すると、残りの持ち分と回復時刻が確認できる
```

| オプション | 意味 |
| --- | --- |
| `/status` | 残りの使用量と次の回復時刻を確認する |

### 📖 `deterministic`（デターミニスティック）

**一言でいうと**: 同じことをすれば必ず同じ結果になる性質。決定的

入力が同じなら結果も必ず同じになる、という性質です。電卓で 2+3 を打てば毎回 5 が出るのと同じです。AIの出力は本質的にこうではなく、Anthropic は temperature を 0 にしても完全には同じにならないと明記しています。だからこそ、確実に毎回同じであってほしい処理（フックなど）はAIの判断に任せず、しくみ側で固定します。

### 📖 `idempotent`（アイデムポテント）

**一言でいうと**: 何回やっても結果が変わらない性質。二度押ししても安全

1回やっても10回やっても最終状態が同じになる操作の性質です。日本語では「べき等」と書きます。エレベーターのボタンを何回押しても同じ階に止まるのと同じで、二重に実行されても壊れません。AIが同じ処理を繰り返してしまう可能性がある場面では、この性質があるかどうかが安全性を大きく左右します。

### 📖 `deploy`（デプロイ）

**一言でいうと**: 作ったものを実際に動く場所へ載せて公開すること

手元で作ったものを、本番のサーバーに載せて実際に使える状態にする作業です。原稿を書き終えて印刷所に回し、店頭に並べるところまでにあたります。ここから先は本物のお客さんに影響するので、戻すのが難しい変更になりがちです。実行の前にはひと言確認するのが原則です。

```
/deploy-staging（本番前の確認用の場所へ載せる、という自作コマンドの例）
```

### 📖 `CI/CD`（シーアイシーディー）

**一言でいうと**: 変更のたびに自動でテストして自動で反映させるしくみ

Continuous Integration / Continuous Delivery の略です。コードを直して送ると、テストや検査が自動で走り、問題なければ自動で反映されるまでの流れを指します。工場のベルトコンベアで検品まで自動化されているのと同じです。Claude Code は GitHub Actions や GitLab CI/CD の中で動かして、レビューや仕分けを自動化できます。

```
GitHub にコードを送ると、Claude が自動でレビューコメントを付ける
```

### 📖 `plugin`（プラグイン）

**一言でいうと**: スキルやフックなどを1つにまとめた、追加パック

スキル・フック・サブエージェント・MCP サーバーをひとまとめにして、一括で導入できる形にしたものです。ソフトの拡張機能と同じで、入れるだけで一式そろいます。名前がぶつからないよう「プラグイン名:スキル名」の形で区別されます。チーム内に配るにはマーケットプレイスというしくみを使います。

```
/vercel:deploy のように「プラグイン名:スキル名」で呼び出される
```

### 📖 `verification loop`（ベリフィケーションループ）

**一言でいうと**: AIに合否を自分で確かめさせ、通るまで直させる回し方

テストの実行やビルド、画面の見比べなど「AIが自分で合否を確かめられる手段」を渡し、通るまで直させるやり方です。1回書いて終わりにさせないための仕掛けです。答え合わせの解答集を渡してから宿題をさせるのと同じで、間違いに自分で気づけます。公式は、これがないと「終わった」と判断しているのはAI自身だけになる、と警告しています。

```
「npm test が通るまで直して」と、合否の基準ごと渡す
```
