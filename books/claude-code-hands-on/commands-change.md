ここからは**実際に何かが変わるコマンド**です。前の章と違い、内容を確認してから Yes を押してください。

とはいえ、全部が危険なわけではありません。**危険度で3段階に分けます。**

| 段階 | 意味 | 対応 |
| --- | --- | --- |
| 🟢 **戻せる** | 変わるが、元に戻せる | 内容を軽く見て Yes |
| 🟡 **戻しにくい** | 手間をかければ戻せる | 対象を確認してから Yes |
| 🔴 **戻せない** | 消える・外に出る | **一度止めて確認する** |

![3本の紐。ほどける蝶結び、絡んだ結び目、切れて床に落ちた紐](/images/claude-code-words-for-office/16-three-cords.png)

## 🟢 戻せるもの

### mkdir — フォルダを作る（make directory）

```
mkdir reports
```

フォルダが1つ増えるだけです。不要なら後で消せます。

### touch — 空のファイルを作る

```
touch memo.md
```

中身が空のファイルが1つできます。

### cp — コピーする（copy）

```
cp 請求書.xlsx 請求書_backup.xlsx
```

**元のファイルは残ります**。増えるだけなので安全です。

:::message
`cp` は「バックアップを取る」ときにも使われます。AI が作業前に `cp` するのは**良い兆候**です。
:::

### git add — コミットの準備をする

```
git add .
```

「次のセーブに含めるファイルを選ぶ」操作です。まだ何も記録されていません。

### git commit — セーブする

```
git commit -m "請求書テンプレートを更新"
```

セーブポイントを作ります。**むしろ安全性が上がる操作**です。`-m` の後ろはメモ（何をしたかの説明）です。

### npm install — 部品を取り寄せる

```
npm install
```

必要な部品をダウンロードします。時間はかかりますが通常は安全です。

---

## 🟡 戻しにくいもの

### mv — 移動する / 名前を変える（move）

```
mv 請求書.xlsx documents/請求書_2026.xlsx
```

**元の場所からは消えます**（`cp` との違いがここです）。移動先が間違っていると探すのが面倒になります。

:::message
確認するポイントは**移動先**です。見慣れない場所に動かそうとしていないか見てください。
:::

### git checkout / git switch — ブランチを切り替える

```
git switch main
```

作業中の変更が残っていると警告が出ます。**保存していない作業が消える場合があるので**、コミット済みかどうかを気にしてください。

### chmod — 権限を変える

```
chmod +x script.sh
```

「このファイルを実行してよい」という設定に変えます。それ自体は普通の操作ですが、**`chmod 777` は「誰でも何でもできる」設定なので避けるべき**です。

### 上書きの `>` （リダイレクト）

```
echo "内容" > memo.md
```

`>` は「**中身を丸ごと書き換える**」記号です。既存のファイルに対して使うと、元の中身は消えます。

| 記号 | 意味 |
| --- | --- |
| `>` | 上書き（**元の中身は消える**） |
| `>>` | 追記（元の中身は残る） |

![左は上から潰して元が消える、右は下に足して元が残る](/images/claude-code-words-for-office/26-overwrite-vs-append.png)

## 🔴 一度止めて確認するもの

:::message alert
ここから先は、**内容を読んで納得できなければ No を選んでください。** 分からないまま Yes を押す価値はありません。AI に「これは何をするコマンドですか」と日本語で聞き返すのが正解です。
:::

### rm — 消す（remove）

```
rm memo.md
rm -rf node_modules
```

**ゴミ箱に入りません。完全に消えます。**

| オプション | 意味 | 危険度 |
| --- | --- | --- |
| `rm ファイル名` | ファイル1つを消す | 中 |
| `rm -r フォルダ名` | フォルダごと中身も消す | 高 |
| `rm -f` | 確認なしで強制的に消す | 高 |
| `rm -rf` | **フォルダを中身ごと確認なしで消す** | 最高 |

`-rf` を見たら必ず立ち止まってください。そして**何を消そうとしているか**を見ます。

```
rm -rf node_modules     ← これは取り寄せた部品なので、消しても入れ直せる（問題ない）
rm -rf documents        ← 書類フォルダ。絶対に止める
rm -rf /                ← パソコン全体。絶対に実行しない
```

つまり `-rf` そのものが悪いのではなく、**対象がなんであるか**が全てです。

### git reset --hard — 変更を捨てて巻き戻す

```
git reset --hard
```

**保存していない作業がすべて消えます。**「やり直したい」ときに使われますが、消える対象を理解していないと事故になります。

### git push — 外部に送る

```
git push
```

自分のパソコンの中の変更を、**GitHub などインターネット上に送ります**。送った後は「なかったこと」にしづらい操作です。

:::message alert
社内資料や顧客情報が混ざったまま `push` すると**情報が外に出ます**。何を送るのかを `git status` で確認してからにしてください。
:::

### デプロイ / 本番反映（deploy）

```
vercel --prod
```

**実際のサービスに反映する**操作です。お客様が見る画面が変わります。必ず担当者に確認してください。

### curl — インターネットと通信する

```
curl https://example.com
```

外部と通信します。情報を**取ってくる**だけなら安全ですが、`-d` などのオプションで**送る**場合は中身に注意が必要です。

### sudo — 管理者として実行する

```
sudo npm install -g something
```

「管理者権限で実行する」という意味で、**パソコン全体の設定を変えられる状態**になります。パスワードを聞かれます。日常の事務作業で `sudo` が必要になる場面はほとんどありません。

### データベース操作（DROP / DELETE / TRUNCATE）

```sql
DROP TABLE customers;
DELETE FROM orders;
```

**データが消えます。** `WHERE` の条件が付いていない `DELETE` は全件削除です。この種の操作は必ず担当者と一緒に行ってください。

## 判断に迷ったときの一言

覚えるのはこの一文だけで十分です。

:::message
**「このコマンドは何を変えますか？元に戻せますか？」と日本語で聞き返す。**
:::

Claude Code は聞かれれば説明します。**聞き返すことは作業の遅れではなく、正しい使い方**です。
